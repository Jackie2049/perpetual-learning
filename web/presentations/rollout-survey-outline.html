1 · 研究问题

LLM post-training（RL / 推理类后训练）中，rollout 阶段的性能由什么决定、可以被系统化优化到什么程度？

范围：rollout-native 系统与论文（L1 token 级 → L4 pipeline 级）+ serving→rollout 迁移分析 + 代码实现对照。

明确不做：reward / 算法本身的改进（只关心其对 rollout workload 的影响）、pretraining、纯 serving 部署。

2 · 核心假设：Serving ≠ Rollout

rollout 不是「serving 换个负载」——两者在请求模型、核心指标、版本与正确性约束上系统性不同。每个调研条目都要回答：它隐含的 serving/rollout 假设是什么？反例单独登记。

维度ServingRollout
请求模型独立用户请求，到达不可控一批 trajectory，同批生成、同步/半同步推进
核心指标TTFT / TPOT / latency / goodputtrajectory throughput、rollout makespan、bubble ratio、GPU-hours、RL step time、time-to-quality
版本约束单一模型权重policy 连续更新 → drafter / cache / 调度决策随版本过期（staleness）
正确性约束输出质量policy 版本、同权重训推数值差异、old logp 语义分别核

3 · 性能模型

Trollout ≈ maxi Ttrajectory,i sync RL 下 makespan 由最慢轨迹支配 —— 平均 tokens/s 高 ≠ rollout 快；长尾 / straggler 是 L3 调度类工作的理论起点

4 · 分类法（Taxonomy）

层（L1–L4，允许反例修订）：

架构分层核心问题代表性技术抓手
L4 RL Pipelinerollout 怎么与其他阶段协同（例如 train/reward/env/weight-update）sync/async（AReaL）、colocated/disaggregated（HybridFlow / veRL）、overlap（StreamRL）、weight sync（LlamaRL）、staleness（PACE）、partial rollout（Laminar）、resource allocation（PivotRL）
L3 Rollout Cluster一批 trajectory set 怎么整体最快（minimize makespan）global scheduling（RollPacker）、length prediction（SortedRL）、straggler/tail（DAS）、migration（DORA）、cache-aware routing（WAR）、elastic（ECHO-2）
L2 Infer Engine一个 engine 如何高效处理一批路由到该实例的trajectoriescontinuous batching（Orca）、chunked prefill（Sarathi-Serve）、prefix/KV reuse（SGLang / RadixAttention）、multi-sample（Infinite Sampling）、sleep/wake（PUZZLE）
L1 Model Execution单 token / decode step 怎么更便宜attention/kernel（FlashAttention-2）、KV cache（vLLM / PagedAttention）、quantization/FP8（FP8-RL）、speculative decoding（Speculative Sampling）、MTP（MTP-RL）、draft model（EAGLE）

三类优化动作（What）

回答：优化究竟改变了什么？

类别优化对象典型方法
A. Make each trajectory cheaper单轨迹计算成本
完成同样的轨迹生成任务，减少计算或重复工作		Spec Decode、MTP、Prefix/KV Reuse
B. Execute trajectory set better一组轨迹的执行方式
改进组批、调度、负载分配与迁移，减少等待和空闲		Batching、Scheduling、Load Balancing、Migration
C. Generate less/better work需要生成的轨迹集合
调整生成哪些轨迹、每个 prompt 生成多少条，以及生成到哪里停止		Early Stopping、Filtering、Adaptive Allocation

三类动作分别改变轨迹成本、集合执行、工作集合本身。L1–L4 回答优化发生在哪里（Where），A/B/C 回答优化改变了什么（What）；两者是独立分类轴，一项工作可以跨层并包含多类动作。

按实际机制分类，不按技术名称分类：partial rollout 若只是暂停后继续、提供预测信号或辅助调度，不自动归 C；若截断、丢弃轨迹或改变采样数量，则包含 C。Filtering 若在完整生成后才进行，不代表节省了本轮生成成本。

C 类可能改变训练数据分布，应同时报告质量、收敛或 Time-to-Quality，不能只比较生成加速比。A/B 也不自动意味着无损；采样分布变化、量化误差与 policy staleness 应另设标签记录。
