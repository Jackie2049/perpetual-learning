国内旗舰模型的 Agent 训练五层技术栈

范围：Qwen / DeepSeek / GLM / Kimi / 混元（Hy3 起）。中心不是又一张型号表，而是：为了让模型会规划、调工具、跟环境多轮交互，后训练栈的哪一层先坏。

读法 1 · 2025-01

Reasoning RL 只真正打穿了「学习目标」（GRPO + 可验证结果）。轨迹短、无工具、常是 dense 或还没把训推引擎拆开，所以 TITO / R3 当时不是瓶颈。

读法 2 · 2025-07

Agent 成为主路径，先打穿「任务与环境」和「rollout 系统」（两万环境、slime、轨迹合成）。学习目标大多还是 GRPO 家族。

读法 3 · 2025-10 起

引擎一拆成异步、模型一变成 MoE、轨迹一变成多轮 tool，第 3 层才爆。R3 和 TITO 都在这一层。DSA / 百万 token 是为了让 L1、L4 的长轨迹在计算上付得起。

按层展开

GRPO 的小变体（DAPO、CISPO 等）不单开。每层只留有代表性、反复被旗舰点名的技术。

L1 · 任务与环境

问的是：模型在跟什么交互、怎样算一次「做对了」。奖励设计附属于环境——环境给不给得出干净信号——不单独成层。

2025-04 原子能力Qwen3 把 agent/工具掺进通用 RL；GLM-4-0414 用拒绝采样 + RL 训 function calling。动作空间扩到 tool call，反馈仍是格式/偏好，不是沙箱跑完测试。这是数据形态起点，不是 AgenticRL。
2025-07 两条分叉Qwen3-Coder：真实环境 RL，约 2 万路并行，SWE / Browser-Use / Tool-Use，环境就是数据源。Kimi K2：先合成工具/任务/轨迹做 SFT，再 Gym 式 RLVR。两条后来一直并存。
2025-12 环境工厂化DeepSeek-V3.2：合成 1800+ 环境、85000+ prompt；agent 用规则结果奖励，通用任务用带 rubric 的生成式 RM；reasoning / agent / 对齐并在一个 GRPO 阶段。
2026-01 可并行分解Kimi K2.5 PARL：只训 orchestrator，冻住子 agent。要评估的是并行调度，不是单条长轨迹。奖励 = 并行实例化 + 完成率 + 任务结果，防假并行和串行塌缩。
2026-04 多 harness · 可暂停V4 的 DSec（函数/容器/microVM/虚机）与 K3 可恢复沙箱：partial rollout 若环境不能暂停，生成省了、交互省不了。K3 训练时轮换 Claude Code / Codex / OpenClaw。
扩缩三角Qwen3.8：Task（单任务→多日）× Workspace（多文件→异构目录）× Harness（类别/版本/skills）独立扩。Universal Reward 把执行检查、文本/视觉 rubric、agent 巡检收进同一套。

这一层的演进一句话：原子 tool call → 单环境长程 → 合成环境工厂 → 并行 / 多 harness → 环境与奖励一起 scale。

L2 · 学习目标

问的是：有了轨迹和奖励之后，用什么式子更新策略。Agent 轨迹变长、模型变 MoE 之后，目标函数的粒度会跟着变；名字可以一直叫 GRPO 家族。

2025-01 GRPO 成为默认骨架。同一 prompt 采一组回复，组内相对优势，不要 value model。它解决的是「长 CoT 上 PPO 养不起 critic」，并不解决多轮工具或 MoE 路由。可验证结果（对错、单测）是配套奖励；环境层后来把「可验证」从数学题换成沙箱，这一层可以暂时不动。

2025-07 GSPO：MoE 上把优化粒度从 token 改到序列。GRPO 对每个 token 算 importance ratio 再 clip；MoE 里 router 稍抖，每个 token 的 rt 都在抖，长序列方差爆炸。GSPO 用整段回复的几何平均做序列级 ratio，clip 一次。

GSPO 与 R3 正交：GSPO 改 loss 粒度，R3 改 是不是同一组 expert。先保证动作定义一致，再考虑 ratio 不要按 token 抖。

之后到 GLM-5、Qwen3.8、K3，公开材料仍是「在 GRPO/GSPO 这类 critic-free 目标上做长程」。真正换的是环境、一致性和 rollout，不是又发明一个 loss 名。

L3 · 训推一致性

问的是：采样时模型做的那个动作，反传时是不是还在对同一个动作求导。可以记成三个「动作必须对上」：

对不上什么代表性技术何时成为问题
token 序列（含 tool / thinking 边界）TITO异步 + 多轮，text 往返再 tokenize
MoE expert 选择R3 / Routing Replay推理引擎与训练引擎各算一遍 router
DSA indexer 的 top-k确定性 top-k / 冻结 indexer稀疏注意力当另一种路由

R3（2025-10）：rollout（vLLM/SGLang）和训练（Megatron 等）数值差会让同一 token 选到不同 expert。重要性采样假设「当前 logπ 对应当初采样的动作」被破坏。做法：rollout 记录每层 top-k expert 索引，训练 forward 强制重放；router logits 仍用当前权重算。只重放离散选择。dense 模型不需要。

TITO（2026-02）：反面是 Text-In-Text-Out——rollout 吐字符串，训练再 tokenize。空白、截断、chat template、tool 消息、</think> 一 decode/encode，采样 token id ≠ 反传 token id。正面：gateway 保存 input_ids / output_ids / logprobs（以及 routed experts），多轮只对新增后缀 tokenize。没有 TITO，异步 + 多轮 tool 的 GRPO 在数学上已经不是对采样动作求导。

IcePop / 双端 IS 修的是策略版本差（异步 off-policy），不是 token 对不齐、也不是 expert 对不齐。先有 TITO 和 R3，再谈 IS。

L4 · 长程 rollout 系统

问的是：一条轨迹要跑很多步、很长生成，一批里总有几条拖到天荒地老，训练还能否向前走。

2025-01　partial rollout（k1.5）：做完一部分就更新，没做完的下一轮接着滚
↓ Agent 轨迹比 CoT 更长、更吃环境，这套直接搬家
2025-07　slime：Megatron 训练 + SGLang rollout + Data Buffer；环境当 data generation 插件接入
↓ 吞吐再升一档
APRIL 超额发请求、主动收部分完成，打 rollout 长尾（生成可占 RL 时间九成以上）
↓ 异步解耦换来的就是 L3
2026-02 异步 + 2026-04 可恢复 microVM：环境状态也必须能暂停，否则只省了 decode

演进：同步等齐 → 部分完成就更新 → 框架化插环境 → 异步 + 可恢复环境。吞吐每升一档，第 3 层就要补一档。

L5 · 长序列模型架构

问的是：多轮工具、保留思考、仓库级上下文，注意力和 KV 是否付得起。架构不直接「训 Agent」，但没有它，上面四层的长轨迹在计算上不成立。

2025-04 快慢思考合一Qwen3：同一套权重，thinking budget 可调。把「推理 token 也要占上下文」变成产品默认。
2025-09 DSAlightning indexer + top-k，装在 MLA 上，主注意力从 O(L²) 降到 O(Lk)。给 L1/L4 让路，同时把 indexer 选择变成 L3 的新一致性问题。
2025-11 交错 / 保留思考工具调用之间不丢掉思考块。这是模板与数据约定，要求 TITO 能正确切 thinking / tool 边界。
2026-02 线性注意力混合Qwen3.5：Gated DeltaNet 与 Gated Attention 交错。目标同样是长序列效率，路线与 DSA 不同（混合线性 vs 选择稀疏）。
2026-04 百万 tokenV4 / K3 / Hy4 / GLM-5.3 Flash。卖点从「窗口数字」变成「agent 用得起的 1M」。架构层到这里和任务层合龙。
