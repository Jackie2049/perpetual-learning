# 气泡归因的分辨率与镜像不可分

2026-11-02，M1。支撑 [rollout 调研主文档 §21.11](../../notebook/rollout-performance-research.md)，补强 §21.10（[同目录的另一份材料](bubble_attribution.py)）。

**不是 GPU 实测，不涉及任何具体系统**。进程内构造的逐格忙／闲轨迹，只用标准库。

## 一句话结论

§21.10 说"B2 与 B3 在 10s 采样下并列"。本批把这句话拆成三件更硬的事：

1. **10s 采样下 B2 的窗口不是"被读成同样长"，是"根本读不到"**——2 秒的窗口在 10 秒采样下
   有相当概率一个采样点都没落进去，整段消失（§21.10 报的 `longest_run=3` 来自构造里的随机重采样，不是采样本身）。
   最小可分辨窗口跟着采样间隔线性走：2s→2 秒、5s→5 秒、10s→**10 秒**、20s→**20 秒**。
2. **同一份逐格轨迹，换一个语义标签，三个统计量逐位相同**。"全体副本同时空闲"既是运行时重叠
   （真空泡），也可能是请求命中了前缀缓存（正常计算，不是气泡）。**判据的输出不是识别，是强制归类。**
3. **份额可加 ≠ 质量可加**。两段不重叠窗口的份额严格可加（0.375＋0.250＝0.625），但其中
   真正是气泡的只有 0.375；"可加"验证的是读数自洽，不是归因正确。

## 为什么做

§21.10 首次把"气泡能不能测"变成可核问题，四条判决都成立，但留下四个没回答的点：

- **该多细采样？** 只给了一个点（2s vs 8s @ 10s 采样）。没有"给定采样间隔，多大的窗口才分得开"。
- **"并列"是读数相同还是都读不到？** §21.10 在粗采样档换了 trace 构造（`n_ticks` 随 tick 变），
  于是那一档的份额（0.06→0.93）与主表的 0.075 不是同一口径，也不能说明"读不到"这件事。
- **判据 30/30 说明什么？** 判据与其核对的机制出自同一个构造器，30/30 里有多少是构造保证、多少是发现，没有分开。
- **可加性证明的是什么？** §21.10 判决五证明同层份额可加，但"可加"不等于"每一份都是气泡"。

## 模型

4 个副本 × 400 格；物理负载固定为"每 100 秒一个窗口"，唯一变量是窗口长度与采样间隔。

**采样的关键不是 `ceil(w/k)`。** 窗口 `[s, s+w)` 落在 `k` 秒栅格上占几格是

```
支撑数 = #{m ∈ ℤ : s/k ≤ m < (s+w)/k}
```

它随偏移 `s` 取两个相邻值（长度 1 的模 1 量）。当 `w/k` 不是整数时，支撑集是 `{n, n+1}`，
**窗口有一半概率整段落在两个采样点之间**——采样只在格边界看，二值化之后这段信息不可恢复。
代码里 `support_spectrum()` 用的是精确枚举，`ceil`／`round` 都会把这件事算错
（`ceil(2/10)=1`，真实最坏情况是 0）。

## 结果

### Q1：给定采样间隔，最小可分辨窗口是多少

判据沿用 §21.10（逐种子比较 `longest_run`），B3 窗长恒为 B2 的 4 倍，30 种子：

| 采样间隔 | 最小可分辨 B2 窗口（30/30） | 对应 B3 窗口 | 低于此值：整段丢失区间 | 混叠带 |
|---|---|---|---|---|
| 1s | 1s | 4s | 无 | 无 |
| 2s | 2s | 8s | 1s | 3,5,7,…（只有 25% 概率可见） |
| 5s | 5s | 20s | 1–4s | 6,7,8,9,11,… |
| **10s** | **10s** | 40s | **1–9s** | 无 |
| **20s** | **20s** | 80s | **1–19s** | 无 |

两点值得记住：

- **最小可分辨窗口 ≈ 一个采样间隔**，不是"一个采样间隔的若干倍"。10s 采样时，9 秒以内的切换裂隙
  **一次都读不到**（`longest_run = 0`），而不是读到相等。
- **存在混叠带**：5s 采样下 6–9 秒的窗口只有约 3/30 次分得开——它会随窗口起点的相位时有时无。
  这比"固定并列"更糟：一次跑通的复现可能纯靠相位运气。

### Q2：同样 10s 采样，窗长要多差才分得开

采样间隔 10s、B2 窗长 10s，只扫 B3/B2 窗长比：

| B3/B2 | 1.0 | 1.2 | 1.5 | **2.0** | 3.0 | 4.0 | 8.0 |
|---|---|---|---|---|---|---|---|
| 分得开（30 种子） | 0/30 | 0/30 | 0/30 | **30/30** | 30/30 | 30/30 | 30/30 |

**门槛在比值 2**，不是 §21.10 隐含的"4 倍也不够"。两个窗口都远长于采样间隔时，
比值 2 就足以分开——所以"10s 采样分不开 B2/B3"的正确表述是
**"当切换裂隙短于 10 秒时分不开"**，而不是"10s 采样天生分不开这两类"。

### Q3：同一份轨迹，两种语义（最要紧）

| 统计量 | 轨迹 A | 轨迹 B |
|---|---|---|
| 轨迹本身 | 同一份 `context_trace()` | 同一份 |
| 标签 | 空闲全来自运行时驱动重叠 | 空闲全来自请求命中前缀缓存 |
| 气泡份额 | 0.375 | 0.375 |
| 同时性 | 1.000 | 1.000 |
| 集中度 | 0.000 | 0.000 |
| 最长连续空闲 | 150 | 150 |

三个统计量**逐位相同**。§21.10 判据把两条都归进 B2/B3 族；但物理上一条是真气泡、
另一条是该算进计算的工作。**轨迹里没有区分它们的信息**——要分开必须引入轨迹之外的证据
（kernel 活动、请求在途状态、KV 命中计数）。

同一个问题的另一半：**全体同时的长窗口（只有一个窗口，运行时重叠）在三个统计量上与 B3 逐位相同**，
份额 0.075／0.150／0.300（窗长 30／60／120 格），同时性 1.0、集中度 0.0。
§21.10 主表的四类机制里少的就是这一个成分。

### Q4：判据的 30/30 有多少是构造保证

- **强制归类**：给一条四类都不是的轨迹（各副本 25% 随机空闲、互不对齐），判据照样给出确定答案
  （本项目里落到 B5 桶，份额 0.267）。判据没有"以上都不是"这一项——它的输出是归类，不是识别。
- **镜像长度**：同时性与集中度逐位相同、份额相差 **5 倍**的两条轨迹，形状判据完全无法排序
  （份额不是形状统计量的输入）。这个 5 倍是**构造决定的上界**：要让集中度保持 1，
  空闲格总数被副本数封顶，份额比 ≤ 副本数。
- **对齐假设**：尾部窗口压在第二段窗口里时并集贡献 0；挪开 40 格后份额从 0.625 变 0.725（Δ=0.1），
  而判据的三个桶一个都没动——**读者看不出这 0.1 从哪来**。

### Q5：可加的是读数，不是质量

| 段 | 物理性质 | 份额 |
|---|---|---|
| 运行时重叠窗口（0–150 格） | 真气泡 | 0.375 |
| 前缀缓存命中窗口（150–250 格） | 正常工作，不是气泡 | 0.250 |
| 尾部空闲（200–250 格，压在上一段里） | 并集贡献 0 | 0.000 |
| **并集** | 份额可加（0.375＋0.250＝**0.625**） | **0.625** |
| **其中真气泡** | 只算第一段 | **0.375** |

§21.10 判决五的"同层可加（ratio = 1.000）"是对的，但它证明的是**读数自洽**：
份额按定义加起来一定等于并集。它不能证明"可加的那一份都该算气泡"。

### Q6：跨口径

§21.10 Q3 那一档的 `n_ticks = ⌈400/tick⌉`、副本恒忙，份额是"trace 内空转格占比"：

| 采样间隔 | trace 格数 | B2 份额 | B3 份额 | 并列 |
|---|---|---|---|---|
| 1s | 400 | 0.060 | 0.230 | 否 |
| 5s | 80 | 0.030 | 0.058 | 否 |
| **10s** | 40 | 0.030 | 0.030 | **是** |
| 20s | 20 | 0.025 | 0.025 | **是** |

0.06 → 0.93 那组数字不是采样造成的：主表用同一 400 格口径。本文件把物理占空比固定在 0.30
后重跑：1／2／5／10s 采样读数都是 0.30（无偏）；20s 掉到 0.20（支撑集 {1,2} 取最坏）；
**50s 采样时整段窗口消失、读数 0.00**。反演式：

```
读到的份额 = min({#m : s/k ≤ m < (s+w)/k}) / ⌈period/k⌉
```

反解窗口长度**不单调**：短窗整段消失（支撑 0），长窗被钉成 ⌈period/k⌉ 分之一取整。

## 对 §21.10／§3.5 的修订（本批已据此改写）

1. **§21.10 判决三改口径**："10s／20s 下并列"的正确表述是"**窗口短于采样间隔时分不开，
   且短窗可能整段读不到**"；同时性判据在窗口 ≪ 采样间隔时不是"低灵敏度"，是**零信息**。
2. **§3.5 边界 1 补第四条**：利用率轨迹无法区分"全体同时空闲"与"请求命中前缀缓存"——
   同理也无法区分运行时驱动重叠与 B2/B3。要分开必须引入轨迹之外的证据。
3. **§21.10 判决二降级**：判据 30/30 是在与判据同源的构造上测的，须标注"含构造保证"；
   判据没有"以上都不是"，不能当作识别器使用。
4. **§21.10 判决五补限定**：同层可加证的是读数自洽，不证质量可加。

## 自查修正（四处，均为跑通后发现）

1. **`ceil` 近似写错采样**：第一版用 `ceil(τ/tick)` 当窗口占领的格数，于是"窗口整段丢失"这个机制
   被结构性排除——而那恰是 10s 采样下 B2 的真实结局。改为精确枚举支撑数后，
   `tick10_s` 的 1–9 秒全部变成"0/30 可分辨"，与"并列"是两回事。
2. **主表的零方差来自构造**：§21.10 的 B3/B5/B4 三个生成器给的是定长窗口，份额方差恰为 0
   （B2 是 0.0723±0.0028，因为它是"多而短"）。这不是发现问题，是构造决定的；
   引用「份额完全重合」时应带这条限定。
3. **两组构造变量混用**：`context_trace` 早先同时收"起点"和"长度"两个参数，第二段被算成
   150–250·100 的错位区间，可加性一度得出"并集 0.375、分项和 0.625"。改为只认 `(起点, 终点)`。
4. **镜像对的份额比值上界**：本想构造 10 倍差的镜像对，实际被"集中度保持 1 需把空闲压在
   少数副本上"这条结构约束卡在副本数倍。上界写成参数而不是写成结论。

## 边界

进程内构造轨迹，**无 GPU／无引擎／无真实监控数据**；格数与窗口长度都是构造参数。
采样模型是**二值忙／闲**，未建模部分占用、多 GPU 协同、网络与存储，也未建模真实监控
（如 DCGM 的采样是平均利用率而非二值）。
**不支持**"某框架的气泡是 X 类"或"某系统应改采样间隔"；
只支持"给定采样间隔与窗口长度，哪几类在原理上分得开、要多少额外证据才分得开"。
