# 气泡归因的可辨识性：只看利用率轨迹，哪几类气泡分得开

2026-11-02，M1。支撑 [rollout 调研主文档 §21.10](../../notebook/rollout-performance-research.md)。

**不是 GPU 实测，不是任何系统的端到端**。进程内构造的逐 tick 忙／闲轨迹，只用标准库。

## 一句话结论

**只看利用率轨迹，B3（权重同步）／B5（colocation 失配）能分开；B4（环境等待）只在"空闲压在少数副本上"时能认出；B2（切换裂隙）与 B3 分不开。**

因为它们的气泡**份额几乎相同**（0.072–0.075），能分开它们的只有**空闲的"形状"**：
- B2／B3 让全部副本在同一瞬间停 → 同时性 = 1.00
- B5／B4 让各副本错开停 → 同时性 = 0.00
- 其中 B4 是"少数副本被卡住"→ 空转集中度 = 1.00；B5 是"各副本各自缺工"→ 集中度 = 0.00

而 **B2 与 B3 在两个统计量上逐位相同，只差窗口长度**（15 vs 2 tick）——
窗口长度是 tick 粒度的函数，采样一粗就并列。

## 为什么做

§3.2 的五类气泡表是本文的承重结构之一，但"能不能测"从未被检验。§3.5 边界 1 只写了一句
"B4 与 B5 在 agentic 负载下会互相掩盖"，没有量化过能分开哪些、靠什么分开。
§21.5 证过 C2 的**事件时间戳**拆分极脆，§21.7 证过报 η 的近似可分性——
本节补的是第三条：**只有利用率轨迹时，空闲时间该归给哪一类？**

## 模型

4 个副本 × 400 个 tick 的忙/闲轨迹（1 = 该副本该 tick 在算）。四类机制各构造一条轨迹：

| 机制 | 构造 |
|---|---|
| **B3** 权重同步 | 2 个长窗口，**所有副本同时**空闲 |
| **B2** 切换裂隙 | 14 个极短窗口（2 tick），**所有副本同时**空闲 |
| **B5** colocation 失配 | 每副本一段，起点**互不重叠** |
| **B4** 环境等待 | 1 个"卡住"的请求，只占**一个副本**的一段 |

三个形状统计量：

- **气泡份额** `1 − 平均利用率`（B5 式口径，把所有空闲算成一类）
- **同时性** `全部副本同时空闲的 tick 数 ÷ 至少一个副本空闲的 tick 数`
- **集中度** 各副本空闲 tick 数的归一化 Herfindahl：全平摊 0、全压一个副本 1

## 结果

### Q1：份额相同，形状不同

| 机制 | 气泡份额 | 同时性 | 集中度 | 最长连续空闲 |
|---|---|---|---|---|
| B2 | 0.072 | **1.00** | **0.00** | 2 |
| B3 | 0.075 | **1.00** | **0.00** | **15** |
| B5 | 0.075 | **0.00** | **0.00** | 30 |
| B4 | 0.075 | **0.00** | **1.00** | 120 |

**四类的气泡份额全部落在 0.072–0.075**——只报"气泡占 7.5%"的论文，读者无从判断是哪一类，
也就无从判断该用哪个杠杆。**可分性完全来自形状统计量。**

### Q2：可执行判据在纯机制上 30/30，但其中一类判不出来

判据：先看同时性 `> 0.5` → 归 B2/B3 族；否则看集中度 `> 0.5` → B4；都不是 → B5。

| 机制 | 判到 B2/B3 族 | 判到 B4 | 判到 B5 |
|---|---|---|---|
| B2 | **30/30** | 0 | 0 |
| B3 | **30/30** | 0 | 0 |
| B4 | 0 | **30/30** | 0 |
| B5 | 0 | 0 | **30/30** |

**注意 B2 与 B3 被判进同一个桶**——这是一个"能区分族、不能区分成员"的判据，
不是全部可分的判据。

### Q3：B2 与 B3 只差窗口长度，而窗口长度对 tick 粒度敏感

同一组事件（切换裂隙 2s、权重同步 8s、各 12 次），按不同 tick 粒度采样：

| tick 粒度 | B2 最长段 | B3 最长段 | B3 > B2 |
|---|---|---|---|
| 1s | 2 | **16** | 是 |
| 2s | 1 | 8 | 是 |
| 5s | 2 | 6 | 是 |
| **10s** | 3 | 3 | **并列** |
| **20s** | 3 | 3 | **并列** |

**10s 粒度下两类彻底不可分。** 而 10s 是很多系统监控的默认采样间隔——
这不是理论忧虑，是常见的实测设置。

### Q4：三个混淆都真实存在

**碎片化**：把随机空闲混进 B3（`random_share` 2%/5%/10%），同时性从 1.000 掉到
0.509／0.307／0.191，判据直接落到"B5"桶：

| 随机空闲比例 | 气泡份额 | 同时性 |
|---|---|---|
| 0% | 0.075 | **1.000** |
| 2% | 0.094 | 0.509 |
| 5% | 0.121 | 0.307 |
| 10% | 0.168 | **0.191** |

**空闲极少**：B3 只占 0.5%/1%/2.5%/6% 时同时性仍为 1.000，但绝对空闲 tick 只有 2–48 个——
统计量的方差大到不能用于单次判读（均值看似漂亮，逐种子波动没有实际意义）。

**混合机制**：B3 窗口里再混一个卡住的请求，同时性从 1.000 掉到 **0.681**（−0.319），
判据仍归 B2/B3 族，但"同时性"这个数已经不能反推 B3 的份额。

### Q5：同层可加、跨层不可加——两件事不冲突

在时间上**不重叠**的两个窗口里分别放 B3 与 B5：份额严格可加（`mixed ÷ (B3+B5) = 1.000`）；
在**重叠**的空闲上再叠一层，并集纹丝不动（`delta = 0.000`）。

**这条是正向对照**：§3.5 边界 2 说"气泡比例不可跨层相加"，指的是 B0（机器周期）与 B1–B5（墙钟）
量纲不同。**同层同口径时是可以相加的**——把它读成"任何两个气泡都不能相加"是过度解读。

## 对 §3.2／§3.5 的修订（本批已据此改写）

1. **§3.5 边界 1 补充实测结论**：B2 与 B3 在利用率轨迹上**结构性不可分**（同时性与集中度逐位相同），
   只能靠窗口长度，而窗口长度在 ≥10s 采样下并列。§21.2 的 C2 已规定拆分需独立 t1/t2 证据——
   本节给出"为什么没有独立证据就分不开"的形状证据。
2. **新增一条可执行判据**（进 §3.2 表后的说明）：报气泡时必须同时报**同时性**与**空转集中度**，
   否则读者无法判断该用哪个杠杆；只报份额时，四类机制的值可以完全重合。
3. **§3.5 边界 2 的澄清**：同层同口径可加（实测 ratio = 1.000、重叠 delta = 0），
   不可加的是跨层量纲。

## 自查修正（三处，均跑通后发现）

1. **B4 生成器退化**：第一版让单个副本整个 100% 空闲，得到"最长连续段 = 400"，那不是长尾拖累而是副本掉线。
2. **B2 与 B3 被写成同形**：第一版两者都生成"少而长"的窗口，形状统计量完全相同——那样结论是错的，
   必须让 B2 是"多而短"，否则"只差窗口长度"这句话没有依据。
3. **`additivity` 的 `min` 拼接放大并集**：第一版用逐 tick 取 min 把两条轨迹合起来，
   在副本错开时把并集放大了（ratio 0.93），却当成"不可加"的证据；改为时间窗不重叠的正确构造后 ratio = 1.000。

## 边界

进程内构造轨迹，**无 GPU／无引擎／无真实监控数据**；tick、副本数、窗口长度都是构造参数，
不对应任何具体系统画像。**不支持**"某框架的气泡是 X 类"——本实验只说明"哪些类在原理上分得开、
需要哪些统计量"；也不支持"应当强制系统报同时性"（那是约定问题，不是本实验的结论）。
轨迹只有二进制忙/闲，未建模利用率的部分占用（0.3 个副本那种）、多 GPU 协同、网络与存储。
12 个单测、`--verify` 连跑两次通过，sha256 见 [run-info.json](run-info.json)。
