# G2 其余四个 C 类机制的同 seed 单开关对照

2026-11-01，M1。支撑 [rollout 调研主文档 §13.29](../../notebook/rollout-performance-research.md)。
不是论文复现，不是 GPU 实测，也不是任何系统的端到端；是进程内 CPU 模拟。

## 一句话结论

**四个 C 类机制都省下了生成量，但没有一个把节省完整兑现到墙钟上。**
动态频率把生成量压到 27.7%，墙钟只降 18.7%；cap 替换一点生成量都没省（1.000），墙钟却降 6.3%——
因为它省的是**训练样本**而不是生成 token。真正把节省带满的是足数取消：只省 1.6% 生成量，
墙钟降 34.0%，因为它砍的是**每一轮的固定成本**（信息组够了就不再发起剩余任务）。

## 为什么做

§13.16 G2 表逐篇核了五个 C 类机制，结论是"全部只报加速与质量终值，无一给净效应"。
P-3（§13.28）用 verl 的 DAPO 组过滤补了第一个示范；本批补其余四个——它们是评审最容易点名的位置：
**"你说别人没做净账，那你自己做一遍"**。

四个机制与出处（逐字确认见主文档 §6.28.3／§6.28.5／§6.32.8）：

| 臂 | 机制 | 来源 | 实现要点（本实验） |
|---|---|---|---|
| `freq` | 动态频率 | DART（2609.23866v1） | 题目成功率 > 0.6 时该题本步只采 2 条而非 8 条 |
| `replay` | 成功回放 | DART | 全败组补 2 条历史成功样本（尚无成功记录时退化为一次重采） |
| `cancel` | 足数取消 | ProRL Agent（2603.18815v1） | 本步信息组（0 < 正例 < k）满 4 个即停止发起剩余任务 |
| `cap` | cap 替换 | QwenGyre（2609.33848v2） | 组内答对率 > 0.8 时把该组截断到 2 条再算优势 |

**与 P-3 的差别**：P-3 是逐层叠加（A→B→C）以归因"省下的钱是哪个手段赚的"；本批是"基线 + 四个单开关臂"，
因为这些机制彼此不构成自然叠加链。另外这些机制**不是 verl 的可配置项**，无法像 P-3 那样照源码抽内核，
只能按论文描述实现——这是本实验相对 P-3 在证据强度上更弱的地方，正文引用时必须写明。

## 实验设计

bag-of-tokens 二分类策略，8 道题、**难度档逐题固定**（0.0–0.75 均匀铺开并打乱）：

- 每题 2 个事实位（logit 由题目难度给定）＋ 12 个填充位（共享参数 θ，另有一个全局难度偏移 δ）；
- 每组 8 条轨迹（GRPO n=8），每步 8 个 prompt 从 8 道题里有放回抽取；
- 30 固定种子 × 300 步，5 个臂共用同一批种子 → 可做配对比较；
- 开局正确率 ≈ 0.44，学习率主档 0.2（另跑 0.1／0.4 两档）。

**难度档为什么必须逐题固定**：如果题目难度会漂移，"按题目身份改变采样量"就不构成系统偏差，
三个机制在本设定里会退化成纯噪声。固定难度档是让它们产生真实收敛效应的必要结构，
也是本实验与 P-3 在模型上的唯一实质差别。

## 口径（必须连同数字一起引用）

墙钟统一换算单位：每条轨迹 = 14、空更新 = 1、有更新步 = 8，步成本 = max(生成, 8)。
**绝对值不可与任何论文报值相除**（§19.1 规则一），只能五个臂之间横向比。

## 结果（30 种子，lr=0.2，300 步）

| 臂 | 最终准确率 | 配对 Δacc（95% CI） | 生成量比 | 生成 tokens/步 | 总成本比 | 到 0.9 墙钟比 | 配对 Δ墙钟（95% CI） |
|---|---|---|---|---|---|---|---|
| base | 0.9997 | — | 1.000 | 896 | 1.000 | 1.000 | — |
| `freq` | 0.9983 | −0.0013（±0.0011） | **0.277** | 248 | **0.277** | 0.813 | −2483（±418） |
| `replay` | 0.9992 | −0.0005（±0.0007） | 1.001 | 897 | 1.001 | 1.001 | +12（±572） |
| `cancel` | 0.9993 | −0.0003（±0.0009） | 0.984 | 882 | 0.984 | **0.660** | **−4510（±528）** |
| `cap` | 0.9990 | −0.0007（±0.0006） | **1.000** | 896 | 1.000 | 0.937 | −836（±360） |

配对区间为 30 对同 seed 的 95% CI（正态近似）。"生成 tokens/步"是实际生成量，"总成本比"是步成本之和的比，
两者在 `cap` 上分离——这一分离本身就是一条结论。

**四条读数**：

1. **省生成量 ≠ 省墙钟**：`freq` 的生成量与总成本都是 27.7%，墙钟只到 81.3%。
   差值来自"每步都要付一次更新"这条地板加上收敛变慢（到 0.9 的步数 13.8 → 14.8）。
2. **`cap` 省的是训练样本，不是生成 token**（生成量比 1.000，墙钟 0.937）：截断发生在采样之后。
   它省墙钟的路径与 `freq` 完全不同——靠收敛略快（步数 13.8 → 12.9）。
   因此"cap 替换"与"动态频率"**不可合并成一个百分比报**。
3. **足数取消是唯一把节省带满的**：只省 1.6% 生成量，墙钟降 34.0%。
   它砍的是每轮固定成本，与收敛速度无关，所以三档 lr 下都极稳定（0.660–0.667）。
   代价写在机制里：**本步训练集合由"哪些组先完成"决定**——ProRL Agent 必须配"跨迭代保留未完成任务"正是为此。
4. **成功回放测不出收益**（成本 1.001、墙钟 1.001、Δ 墙钟 +12 ± 572 跨 0）：
   本设定里全败组占比低。**不能读成"回放无害"**——它只在全败组罕见时无害，而那恰是 DART 报告的高质量场景，
   负例场景本实验没有覆盖。

**准确率只能写"没观察到显著退化"**：四臂配对 Δacc 全为负，`freq`（±0.0011）与 `cap`（±0.0006）区间不跨 0，
`replay`／`cancel` 跨 0。但逐种子看，30 个种子里 22–28 个是"基线与臂都满分"的平局，
差异集中在少数种子（`freq` 7 个更差、1 个更好）。**不得写"验证了无收敛代价"。**

## 学习率敏感性（0.1／0.2／0.4，"成本比／到 0.9 墙钟比"）

| lr | `freq` | `replay` | `cancel` | `cap` |
|---|---|---|---|---|
| 0.1 | 0.296／0.765 | 1.002／1.011 | 0.969／0.667 | 1.000／0.950 |
| 0.2 | 0.277／0.813 | 1.001／1.001 | 0.984／0.660 | 1.000／0.937 |
| 0.4 | 0.266／0.849 | 1.001／1.041 | 0.992／0.660 | 1.000／0.957 |

方向全部不变。两处随 lr 移动但不改结论：`freq` 的墙钟节省随 lr 升高而收窄（0.765 → 0.849），
因为 lr 大时收敛步数少（30.8 → 6.6）、"还没触发降频"的前期步占比更高；`cancel` 极稳定（0.660–0.667），
因为它省的是轮内固定成本，与收敛速度无关。

## 与 P-3 合起来看（两者必须并排引用）

| | P-3（DAPO 组过滤，§13.28） | 本批（其余四个 C 机制，§13.29） |
|---|---|---|
| 主结论 | C 在墙钟上**不优于**同批的 B 类早停 | 四个机制**都省生成，多数省不到墙钟上** |
| 成因 | 省下的量全部来自捆绑的早停 | 省下的量落在"每步必做的固定成本"之内 |
| 共同结论 | **C 类机制的收益必须扣除"改变训练集合带来的收敛代价"，代价的兑现位置在更新侧而非生成侧** | |

这是 §3.1 `T_step = T_rollout + T_update + T_sync` 与 §11 条目 3 阶段占比恒等式在 C 类机制上的具体化，
可直接作为 §18 第 7 章（L4 RL Pipeline）"改变集合的机制"一节的论点骨架。

## 不成立的推论（禁止写进正文）

- **不成立**："动态频率省了 72% 墙钟"——27.7% 是生成量口径，墙钟 81.3%。
- **不成立**："足数取消省 34% 且无损"——它省的是轮次，训练集合由完成顺序决定；
  本实验的单峰任务恰好没暴露这层代价。
- **不成立**："成功回放无害"——只覆盖全败组罕见的情形。
- **不成立**：任何一臂的数字都不能与 DART／ProRL Agent／QwenGyre 的报值相除。

## 复跑

```sh
cd experiments/rollout-p4-c-mechanisms
python3 c_mechanisms_ablation.py                        # 5 臂 × 30 种子 × 300 步，约 60 秒，写 summary.json
python3 c_mechanisms_ablation.py --verify summary.json    # 重跑并与归档逐字段比对
python3 analyze.py --json net_wallclock.json              # 固定训练预算 T 的净墙钟扫描
python3 lr_sensitivity.py                                 # 三档 lr，约 170 秒，写 lr_sensitivity.json
python3 lr_sensitivity.py --verify                        # 同上，比对 lr 表
```

仅用 Python 标准库（本机 Python 3.9.6）。两条 `--verify` 均在本机重跑通过；执行条件与产物 sha256 记在
[run-info.json](run-info.json)。
