# 真实 rollout 的响应长度结构：§13.38 的「realistic」组内相关高估了约一倍，但两个主读数几乎不动

**对应**：[rollout 性能调研主文档 §13.50](../../notebook/rollout-performance-research.md)，补 [§13.38](../rollout-minibatch-baseline-bias/readme.md) 的未测项。
**日期**：2026-11-02（M5 算力侧，第五十四批）。**状态**：已完成；5 次采样、5 个分析档、`verify.py` exit 0。

## 一句话结论

**§13.38 里那个"真实长度结构"是构造的（`realistic = cv_group 0.60 / cv_in 0.08`，隐含组内相关 ≈0.98），真实模型上量出来是 `(0.16, 0.17)`（`max_tokens=256`）到 `(0.36, 0.32)`（不截断），组内相关 **0.36–0.52**。** 但这个参数不是 §13.38 两个主读数的敏感源：`ldm/grouped = 1.0462 → 1.044–1.048`、`interleaved/ldm = 1.0045 → 1.0027–1.0065`，全部在 1 SE 内。**另记一条模型层事实**：`max_response=256` 会截断 **45%（1.5B）／61%（0.5B）** 的响应，长度分布不是自由分布而是压在硬上限上。

## 为什么做

§13.38 的两处残留都写在同一句里：

> 「长度为构造分布（真实模型里同 prompt n 条响应的长度相关性**本批未测**）」

这句话决定了它的 `realistic` 档是否可信。该档的含义是"同 prompt 的 n 条响应几乎等长、组间差别大"；而真实 GRPO 里同一 prompt 的 8 条响应长度差异有多大、是否真的高度相关，此前没有任何读数。M5 侧登记的剩余算力事项恰好为空，而这是一件**单卡几分钟就能补完、且直接服务 TS-001 模型层**的事。

## 结果一：长度结构（n=8，480 组）

| 臂 | cv_group | cv_in | ICC(1) [95% CI] | ICC 对数尺度 | 截断率 | 均值长度 |
|---|---|---|---|---|---|---|
| **1.5B cap256（RL 配置）** | **0.161** | **0.166** | **0.450 [0.409, 0.489]** | 0.398 | **45.3%** | 217.1 |
| 1.5B cap256 seed43 | 0.158 | 0.167 | 0.435 [0.396, 0.475] | 0.376 | 45.7% | 218.0 |
| 1.5B 不截断（1024） | 0.356 | 0.323 | 0.522 [0.468, 0.573] | 0.499 | 0.0% | 267.5 |
| **0.5B cap256** | **0.115** | **0.138** | **0.364 [0.321, 0.407]** | 0.320 | **60.8%** | 232.0 |
| 0.5B 不截断（1024） | 0.335 | 0.381 | 0.394 [0.357, 0.437] | 0.432 | 0.7% | 323.2 |
| *§13.38 `realistic`（构造）* | *0.600* | *0.080* | *0.983（同一估计器下的隐含值）* | — | — | *200* |

- **构造档的组内相关接近 1，真实值只有它的一半**：`realistic` 假设组内几乎等长（cv_in 0.08），实测组内离散比组间离散还大（cap256 下 0.166 vs 0.161）。方向不是"组内更齐"，而是"组间差异很小、组内差异很大"。
- **两个模型同一序**：0.5B 的 ICC 更低（0.36 vs 0.45），与参数量一致。
- **n=4 子集**（`rollout.n=4` 的真实档）：0.491（1.5B）／0.396（0.5B），与 n=8 同序，差异在抽样误差内。
- **seed 重复**：ICC 0.450 vs 0.435、截断率 45.3% vs 45.7%，跨种子稳定。

## 结果二：`max_response=256` 是硬约束，且藏着一个读数陷阱

1.5B 有 **45.3%**、0.5B 有 **60.8%** 的响应在 256 token 处被截断（`finish_reason=length`）。抽查确认是模型真的在长篇推理（样本尾部是未写完的解题过程），不是 template／EOS 问题；正常结束的样本以 `#### 答案` 收尾。

**陷阱**：若只用"整组 8 条都没撞上限"的干净组重算，1.5B 的 ICC 会掉到 **0.174**（67 组）、0.5B 掉到 **0.128**（28 组）。这**不能**读成"截断把 ICC 抬高了"——它是选择偏差：条件于"8 条都 <256"等于选走了短答案组并砍掉上尾。真正的无截断读数由 1024 臂给出（**0.522／0.394**）。截断的实际方向是**压低** ICC（0.522→0.450、0.394→0.364），因为组间方差被硬上限压得比组内更多（cv_group 0.356→0.161）。这条写在这里，防止后续会话误引 0.17。

## 结果三：prompt 长度 → 响应长度

| 臂 | Pearson | Spearman |
|---|---|---|
| 1.5B cap256 | 0.441 | 0.484 |
| 1.5B 不截断 | 0.521 | 0.487 |
| 0.5B cap256 | 0.367 | 0.422 |
| 0.5B 不截断 | 0.477 | 0.463 |

prompt 长度只解释响应长度方差的 13–27%，**不足以替代 prompt 身份**——同 prompt 的响应确实共享一个均值（ICC 0.36–0.52），但不是由 prompt 长短单一决定的。

## 结果四：回代 §13.38（三档对照）

用 §13.38 原封不动的 `_grad_model(ρ=0.5)`、LDM 复刻（`karmarkar_karp`）与块噪声比，只替换长度来源。30 个种子、每次重抽 32 组、K=4：

| 长度来源 | `ldm/grouped` | `interleaved/ldm` | ≥1 的种子 | 每块组数（32 组中） |
|---|---|---|---|---|
| 构造 `realistic`（0.60, 0.08） | 1.0462 ± 0.0033 | 1.0045 ± 0.0007 | 90% | 29.84 |
| 实测参数、高斯重抽（1.5B） | 1.0453 | 1.0053 | 97% | 29.11 |
| **真实组重抽（1.5B cap256）** | **1.0471** | **1.0036** | **87%** | **30.82** |
| **真实组重抽（0.5B cap256）** | **1.0480** | **1.0027** | **77%** | **31.34** |
| 真实组重抽（1.5B 不截断） | 1.0445 | 1.0061 | 97% | 28.90 |
| 真实组重抽（0.5B 不截断） | 1.0440 | 1.0065 | 97% | 28.77 |

- **主读数在 1 SE 内不动**：`ldm/grouped` 1.0462 → 1.044–1.048；`interleaved/ldm` 1.0045 → 1.0027–1.0065。**§13.38 的结论对长度结构参数不敏感**，这是本批最有用的一条：那个参数虽然标错了名字，但没有改变任何结论。
- **纯度反而更高**：真实 LDM 每块装 30.8–31.3 个组（构造档 29.8），`intact_groups` 恒 0 ⇒ §13.38 的分解（基准偏差 ≈0.09%、真实组成效应占 ≈98%）在真实数据上**更成立**。
- **截断把两块结构推向"打散"端**：cap256 臂的每块组数（30.8／31.3）高于不截断臂（28.9／28.8），因为 45–61% 的样本长度相同（256），LDM 对相等权重会像 `degenerate` 档那样把组摊到所有块。方向与 §13.38 的退化档一致，量级约 1 SE，只能算支持性证据。

## 读法：改什么、不改什么

- **改**：§13.38 的 `realistic` 标签与参数。真实档应写成 `(0.16, 0.17)`（cap256）／`(0.36, 0.32)`（不截断），ICC 0.36–0.52；"同 prompt 长度强相关"这句话要带模型与截断条件，不能当作接近 1 的强假设。
- **改**：任何引用"组内长度几乎一样"的推理（LDM 把同组排在一起的直觉）要重新表述——真实组内离散与组间同量级，同组在长度序上并不聚成一团；只是 LDM 的分片仍会把每个组摊到全部块（纯度 30.8/32），这才是 §13.38 结论稳的原因。
- **不改**：`ldm/grouped ≈ 1.05`、`interleaved/ldm ≈ 1.004` 两个量级，以及 §13.32 的 1.0508 读法（口径订正部分不动）。
- **新增模型层事实**：`max_response=256` 在 1.5B／0.5B＋gsm8k 上截断 45%／61%。任何以"响应长度分布"为前提的调度收益，在这类小模型短答案任务上都要先看截断率——分布右尾被硬砍。

## 边界与未测

- 单数据集（gsm8k）、两个小模型（Qwen2.5-1.5B/0.5B-Instruct）、单栈（vLLM 0.24.0）、两个种子。**没有跨模型家族与跨数据集的读数**，不想当然外推。
- ICC 是一因素随机效应估计（ANOVA），长度右偏；对数尺度 ICC 一并报出（0.32–0.50），结论不变。
- `structure_n8_clean_groups` 是**选择偏差**档，仅用于说明陷阱，不作估计量。
- 回代分析沿用 §13.38 的梯度模型 `ρ=0.5` 与 30 种子；长度只进入 LDM 排序，不进入梯度结构。
- 采样是**纯推理**，未跑 RL 训练；真实训练中随策略演化长度会漂移，本批只代表"训练早期、gsm8k、T=1.0"的静态切面。
