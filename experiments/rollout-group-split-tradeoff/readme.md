# 拆 GRPO 组的代价与收益：§15 Q5 的首次量化

2026-11-02，M1。支撑 [rollout 调研主文档 §13.30](../../notebook/rollout-performance-research.md)、
补 [§15 Q5](../../notebook/rollout-performance-research.md) 与 [§11.2 条目 7](../../notebook/rollout-performance-research.md)。
不是 GPU 实测，是进程内解析＋仿真的层进模型（第二批补入 L4 训练侧）。

**第二批（同日晚）改了什么**：补 L4（训练侧组级均衡，与真实 verl 逐位交叉验证）；
**并撤回第一批的一个核心证据**——"跨组排序翻转 32.8%／49.3%"经识别性检验证明对组难度零敏感，
量的是估计噪声而非尺度错配，已换成尺度错配与幅度倍数。结论的方向不变（组完整性保护的是
"跨组样本进同一梯度时的幅度可比"），但**证据换了、数字也换了**。

## 一句话结论

**拆组不改变组内比较，但把"同一原始偏离进梯度时的幅度"改掉了；在调度侧能不能省钱取决于一个此前没人说清的假设——队列里有没有积压。**
按 GRPO 的组内归一化（verl `core_algos.py:306-321`、OpenRLHF `experience_maker.py:256`），拆组**不改变组内两两排序**（缩放同一常数）。
真正的代价在尺度：离组均 −2 个原始单位的样本，在片内归一化后只剩整组口径的
**0.69 倍（p=2）／0.41 倍（p=4）**；分片 σ 与整组 σ 的比值中位数 1.09／1.78、P90 达 2.01／9.70。
（第一批报的"跨组排序翻转 33%／49%"已撤回——识别性检验显示它对组难度零敏感，量的是估计噪声。）调度侧的"分组税"在**无积压时为 0（与 §14 候选 D 一致）**，
有 4 批积压时升到 44%，组内长度离散度从 0.2 到 1.5 时税从 21% 升到 57%。

## 为什么做

§15 Q5 原文：**语料内所有 L3 长度调度都以"组不可拆散"为默认前提，但无一篇量化"若允许拆组能多回收多少气泡、组内比较的统计代价是多少"**。
本批把两侧放进同一个可算模型，给出首次读数。这也回答 §11.2 条目 7 那句"语料内无人量化拆组的代价与收益"。

## 模型

三层，逐层可核；随机性全部来自 `random.Random(seed)`，30 种子 × 8 seed 抽样。

| 层 | 量什么 | 怎么算 |
|---|---|---|
| **L1 统计** | 拆成 p 片后归一化统计量的抽样方差；组内／跨组排序翻转 | 解析（χ² 近似 `(n−1)/(n/p−1)`）＋ bootstrap 仿真 |
| **L2 调度** | "分组税"：同一批工作量、同一容量下，整组原子归还 vs 逐条归还的 makespan 差 | FIFO 连续批处理排程 |
| **L3 判据** | 税的上限是否压得过信噪比的下降 | 两侧同表 |
| **L4 训练侧**（第二批补） | DP 分区残余不均衡；组是否跨分区；int64 饱和边界 | verl `karmarkar_karp` 逐位复刻 + 组级／逐条／不均衡三口径对照 |

**关键的口径设计（也是本批最主要的发现）**：分组税只有在**有排队**时才存在。一批工作量一次放得下时，
整组归还与逐条归还给出完全相同的 makespan——这与 §14 候选 D 的实测（AR 下 MIX/H2048=1.000）**不矛盾，是同一个事实**。
`consistency_with_candidate_d` 一栏把候选 D 那一格放进本模型复算，结果正是 0。

## 结果

### L1 统计侧

| 组大小 n | 拆分 p | 分片大小 | σ̂ 方差膨胀（仿真） | χ² 解析界 |
|---|---|---|---|---|
| 8 | 1 | 8 | 1.00 | 1.00 |
| 8 | 2 | 4 | **1.88** | 2.33 |
| 8 | 4 | 2 | **3.05** | 7.00 |
| 16 | 2 | 8 | 1.95 | 2.14 |
| 16 | 4 | 4 | 3.70 | 5.00 |
| 4 | 4 | 1 | — （不可用） | — |

**读数一：仿真膨胀比始终低于 χ² 解析界**（1.88 vs 2.33、3.05 vs 7.00）。解析界假设分片间独立同方差，
实际分片共享同一个组均值，这部分共同项把方差压下来了。**引用时应报仿真值，解析界只能当上界。**

**读数二：p=4、n=4 那一格必须作废，不能写成 0。** 分片只有 1 条时样本标准差未定义——
这是定义域外，不是"零方差"。本批第一版就是在这里错了（把它算成"伪零方差 100%"），现由 `fragment_size` 与 `note` 字段显式标出。

**读数三：组内排序拆组后完全不变；但"跨组排序会被读反"这个说法被本批自己推翻了。**

| 拆分 | 组内两两排序翻转 | 分片 σ / 整组 σ（中位 / P90） | 同一原始偏离的 \|adv\| 倍数 |
|---|---|---|---|
| p=1（不拆） | 0 | 1.00 / 1.00 | 1.00 |
| p=2 | **0** | 1.09 / 2.01 | 0.69 |
| p=4 | **0** | 1.78 / 9.70 | 0.41 |

**组完整性保护的不是"组内比较"**（组内比较在任何拆分下都自洽，因为归一化是组内的），
但"保护的是跨组可比"这句话需要换证据：

- 归档里的 32.8%／49.3% 是**"组内最大值"口径**的翻转率。识别性检验显示它**对组难度方差零敏感**——
  把组难度方差从 0 拉到 25，翻转率一动都不动（极差 0.0），而组难度方差为 0 时它仍给出同样高的翻转率。
  **说明它量的是 σ̂ 与组内最大值之间的统计耦合，不是拆组造成的尺度错配。**
- 换成配对样本口径也不行：翻转率同样在 0.15／0.24 附近且对组难度方差零敏感。
- **有识别性的量是尺度错配本身**：同一原始偏离量（离组均 −2 个原始单位）在片内归一化后
  只剩整组口径的 **0.69 倍（p=2）／0.41 倍（p=4）**；分片 σ 与整组 σ 的比值中位数 1.09／1.78、
  P90 达 2.01／9.70。**这就是"跨组尺度被打散"的可测量含义**——同一原始偏离，进梯度时的幅度不同。

所以 §11.2 条目 7 的表述应为：**组完整性保护的是"跨组样本进同一梯度时的幅度可比"**，
而这一条的量化靠尺度错配与幅度倍数，不靠排序翻转率（该指标已撤回，见下方修正四）。

### L2 调度侧：分组税

| 变量 | 取值 | 分组税（mean） |
|---|---|---|
| 积压批数 | 1 / 4 / 16 | **0.0%** / 43.7% / 54.7% |
| 组内长度离散度 cv | 0.2 / 0.6 / 1.5 | 20.6% / 43.7% / 56.6% |
| 组大小 n | 2 / 4 / 8 | 27.7% / 38.6% / 43.7% |

**读数四：税的全部来源是"排队时整组扣着槽位不放"。**积压从 1 批增到 4 批，税从 0 跳到 44%——
这不是组大小的函数，而是**并发压力**的函数。语料里没有任何一篇报过自己训练时队列的积压深度，
所以"拆组能省多少"这个问题**在现有报道口径下无法回答**，只能给条件式结论。

**读数五：组越大、组内越不齐，税越高。**n 从 2 到 8 税从 28% 升到 44%；cv 从 0.2 到 1.5 税从 21% 升到 57%。
方向上与"组完整性是硬约束"的直觉一致，但**量级取决于负载**，不能当常数引用。

### L3 判据

| 项 | 值 |
|---|---|
| p=2 拆分的 σ̂ 方差膨胀 | 1.88× |
| 优势信噪比比值 | 0.729（即下降 27.1%） |
| 分组税上限（最宽松负载，cv=1.5） | 61.3% |
| 判决 | **需逐负载判断** |

**读数六：判据是"税 > 信噪比损失"才能转正，两侧都跨得很大，所以不能给单一结论。**
在 cv=1.5 且有积压的负载上，税（57–61%）压得过信噪比损失（27%），拆组可能净正；
在无积压或组内齐整（cv=0.2、税 21%）时，拆组净负。
**这条判据还是必要非充分条件**——它没算上拆组带来的 KV 搬运、跨批版本一致性与 §13.13 五族的可比性损失。

## L4 训练侧：verl 的组级均衡（2026-11-02 第二批补）

前三层都在问"调度器该不该拆组"。这一层问**拆了之后，训练侧要付多少代价才能把组重新对齐**——
因为 verl 里已经有这个开关了：`use_prefix_grouper`（默认 `false`）打开后，`_balance_batch`
从"逐条 LDM 划分"改成"先按 uid 聚合整组、再对组做 LDM 划分"（`seqlen_balancing.py:554-621`），
并且强制 `num_groups % dp_size == 0`（`ray_trainer.py:1170-1176`）。

**做法**：把 verl 的 `karmarkar_karp` 逐位复刻（只用标准库），三条口径同 seed 对照——
组级 LDM、逐条 LDM（默认路径）、不均衡按 uid 连续切。32 组 × 组大小 8 × dp∈{2,4,8} × 30 种子。

**LDM 复刻与真实 verl 逐位核对过**：180 组输入（60 组随机样本 × 3 个 dp）给出完全相同的分区，
不一致 0。

| 组内长度离散度 cv | 组级 LDM 残余不均衡（均值 / 最大） | 不均衡基线（均值 / 最大） | 组级 / 不均衡 |
|---|---|---|---|
| 0.2 | **0.08% / 0.57%** | 2.96% / 9.20% | 2.7% |
| 0.6 | **0.23% / 1.18%** | 8.26% / 25.52% | 2.7% |
| 1.2 | **0.34% / 2.73%** | 12.96% / 42.29% | 2.6% |

**读数七：组完整性在训练侧的定价很低，但闭环严格。**
组级 LDM 的残余不均衡只有不均衡基线的 **2.6%**，绝对值 0.08%–2.7%；
而**默认路径（逐条 LDM）几乎必然把每组拆开**——99.65% 的 (种子, dp) 组合里至少有一组跨了分区。
所以 `use_prefix_grouper` 不是"可选优化"，它和 prefix 共享是**同一个前提的两面**：
不改成组级均衡，prefix 共享在训练侧根本用不上。

> **2026-11-02 订正**：上面这条只说明"默认路径会拆组"，**不能说成"所以拆组代价已在付"**。
> verl 是 `_balance_batch` 重排之后才按 uid 算 GRPO 的 mean/std，拆组只改样本落点
> （DP rank／mini-batch），不改归一化口径。另见
> [../rollout-group-split-training-side/](../rollout-group-split-training-side/readme.md)
> （§13.31）：三个候选统计代价实测全为零。「均衡质量 2.6%」这一读数不受影响。

**读数八："纳秒截断"这条在可训练范围内不成立。** `calculate_workload` 返回 int64，
`int(...item())` 在 exact 值越过 2^63 时饱和，对应序列长度 **3,036,988,213**（约 30 亿 token）。
常规长度（512 / 32768）截断损失恒为 0。**真实机制是离散性而非截断**：
组级均衡一次只能移动整组 8 条，单组权重是 LDM 的最小不可分单位。

**读数九：拆分实现本身的差别比拆分度更大。** 如果真允许拆组，朴素等分（按顺序切 k 片）
在一个 n=8 的组内留下 5.8%–26.6% 的不均衡，而按 LDM 拆只留 0.8%–5.1%——差 5.2–7.9 倍。
**所以"拆组"这个动作的代价，取决于怎么拆**，不能把"不拆"和"拆"当成二值选择。

**读数十：拆组不只放大 σ̂ 的方差，还把它的期望压低。**
L1 之前只报了方差膨胀（1.88×、3.05×），这一批补上期望：分片 σ̂ 的均值只有整组的
**88.4%（p=2）、62.5%（p=4）**。σ̂ 偏小会**放大**优势幅度，这正是跨组尺度被打散的微观机制——
不是"噪声变大"那么简单，而是**分片自己的尺度变小、于是分片内每个样本都显得更极端**。

## 这次自查修正了什么

本批的建模错误比结论更值得记，全部是**先跑出看着合理的数字、再回头推翻**：

1. **组臂与轨迹臂不是同一 workload**。初版组臂只跑 `max(g)` 一条、轨迹臂跑全部 n 条，
   等于给轨迹臂多算 n 倍工作，量化出的"收益"纯属口径错误。现在两臂吃同一批轨迹，唯一差别是归还粒度。
2. **`_makespan` 在没有 pending 时把 `now` 直接推到全部结束**，吃掉了轨迹调度的优势，使税恒为 0。
3. **"伪零方差率"把 p=4、n=4 算成 100%**，而那是样本标准差未定义的定义域外情形。
4. **"组内排序翻转率"恒为 ~50%**：初版把组内归一化与跨组归一化混在一个指标里，两边各算各的，
   得到的是随机数而不是效应。现在拆成"组内翻转（恒为 0）"与"跨组翻转（随 p 上升）"两个量。

第 1、2 条由手工追踪一个小例子发现（`[[1,1,1,1],[9,9,9,9]]` 这种两档长度，手算 makespan 才看出臂间工作量不等），
第 3、4 条在写单元测试时被语义检查抓出。四条都写成了测试。

**第二批（2026-11-02，L4）新增三处修正**，同样是"先跑出看着合理的结果、再回头推翻"：

5. **组完整性检查用错坐标系**。初版拿"按 uid 连续布局的下标"去对照 LDM 重排后的分区，
   两套坐标系混用，结论成了"默认路径恒不拆组、组级均衡反而更差"（自相矛盾）。
   修正后按 uid 连续布局判定，并与真实 verl 180 组交叉验证确认分区逐位一致。
6. **饱和长度二分边界写错一位**：首轮返回 3036988213 的相邻值（不变式 `lo..hi` 维护有误），
   改为显式维护 `workload(lo) ≤ MAX < workload(hi)` 后得到 3036988213，与直接手算一致。
7. **L1 漏报了 σ̂ 的期望偏移**。只报方差膨胀会让读者以为拆组的代价纯粹是"噪声变大"；
   实际 σ̂ 的均值同时被压低（p=2 到 88.4%、p=4 到 62.5%），方向是**放大**优势幅度。
   已补 `test_splitting_biases_sigma_hat_downward`。
8. **（最严重）"跨组排序翻转率"这个指标本身无效**。它对本模型的关键参数——组难度方差——
   **零敏感**：方差从 0 拉到 25，p=2／p=4 的翻转率恒为 0.15／0.24。也就是说，
   第一批把 32.8%／49.3% 解释成"拆组破坏了跨组可比"，是**把估计噪声当成了效应**。
   已用识别性检验（`_iid_counterfactual`）钉死，并换成有识别性的尺度错配度量；
   三条测试 `TestRetractedMetric` 防止它换个名字回来。

## 边界（引用时必须一并写）

- **进程内解析＋仿真**，没有 GPU、没有真实引擎、没有 verl 跑起来。墙钟是任意虚拟秒，
  **不可与任何论文报值相除**（§19.1 规则一）。
- **分组税是上界**：假设后续轨迹随时可接、无跨批版本一致性与 KV 搬运成本。真实收益只会更小。
- **积压批数是构造参数**，不是从任何系统拟合的；语料内没有系统报过这个量。
- **L1 的奖励模型是高斯近似**（组均值 N(0,1)、单条噪声 N(0,0.25)），不覆盖 0/1 奖励的全部分布形态。
- **不支持**"某系统应该/不应该拆组"这类结论；只支持"拆组的两侧各有多大，以及调度侧的答案取决于积压深度"。
- **L4 的输入长度分布是构造参数**（cv 扫描），不是从任何训练日志取的；
  LDM 分区算法与真实 verl 逐位一致，但这只保证"给定输入下算得对"，不保证"输入像真实负载"。
- **L4 与 L2 不可相加**：L2 量的是 rollout 侧组粒度占槽位的成本，L4 量的是训练侧 DP 分区的残余不均衡，两者是不同阶段的账。
- §13.30 与本文件是同一项成果的两处呈现：**正文给判据与读数，过程与修正留在本文件**。
