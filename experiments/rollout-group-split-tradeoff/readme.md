# 拆 GRPO 组的代价与收益：§15 Q5 的首次量化

2026-11-02，M1。支撑 [rollout 调研主文档 §13.30](../../notebook/rollout-performance-research.md)、
补 [§15 Q5](../../notebook/rollout-performance-research.md) 与 [§11.2 条目 7](../../notebook/rollout-performance-research.md)。
不是 GPU 实测，是进程内解析＋仿真的两层模型。

## 一句话结论

**拆组在统计侧几乎"不花代价，但把整组优势的尺度打散了"；在调度侧能不能省钱取决于一个此前没人说清的假设——队列里有没有积压。**
按 GRPO 的组内归一化（verl `core_algos.py:306-321`、OpenRLHF `experience_maker.py:256`），拆组**不改变组内两两排序**（缩放同一常数），
但把不同组的样本放进同一次梯度更新时，**跨组排序在 p=2 时有 33%、p=4 时有 49% 被读反**；
而这些样本的优势尺度差异正是"哪一组该多更新"的依据。调度侧的"分组税"在**无积压时为 0（与 §14 候选 D 一致）**，
有 4 批积压时升到 44%，组内长度离散度从 0.2 到 1.5 时税从 21% 升到 57%。

## 为什么做

§15 Q5 原文：**语料内所有 L3 长度调度都以"组不可拆散"为默认前提，但无一篇量化"若允许拆组能多回收多少气泡、组内比较的统计代价是多少"**。
本批把两侧放进同一个可算模型，给出首次读数。这也回答 §11.2 条目 7 那句"语料内无人量化拆组的代价与收益"。

## 模型

三层，逐层可核；随机性全部来自 `random.Random(seed)`，30 种子 × 8 seed 抽样。

| 层 | 量什么 | 怎么算 |
|---|---|---|
| **L1 统计** | 拆成 p 片后归一化统计量的抽样方差；组内／跨组排序翻转 | 解析（χ² 近似 `(n−1)/(n/p−1)`）＋ bootstrap 仿真 |
| **L2 调度** | "分组税"：同一批工作量、同一容量下，整组原子归还 vs 逐条归还的 makespan 差 | FIFO 连续批处理排程 |
| **L3 判据** | 税的上限是否压得过信噪比的下降 | 两侧同表 |

**关键的口径设计（也是本批最主要的发现）**：分组税只有在**有排队**时才存在。一批工作量一次放得下时，
整组归还与逐条归还给出完全相同的 makespan——这与 §14 候选 D 的实测（AR 下 MIX/H2048=1.000）**不矛盾，是同一个事实**。
`consistency_with_candidate_d` 一栏把候选 D 那一格放进本模型复算，结果正是 0。

## 结果

### L1 统计侧

| 组大小 n | 拆分 p | 分片大小 | σ̂ 方差膨胀（仿真） | χ² 解析界 |
|---|---|---|---|---|
| 8 | 1 | 8 | 1.00 | 1.00 |
| 8 | 2 | 4 | **1.88** | 2.33 |
| 8 | 4 | 2 | **3.05** | 7.00 |
| 16 | 2 | 8 | 1.95 | 2.14 |
| 16 | 4 | 4 | 3.70 | 5.00 |
| 4 | 4 | 1 | — （不可用） | — |

**读数一：仿真膨胀比始终低于 χ² 解析界**（1.88 vs 2.33、3.05 vs 7.00）。解析界假设分片间独立同方差，
实际分片共享同一个组均值，这部分共同项把方差压下来了。**引用时应报仿真值，解析界只能当上界。**

**读数二：p=4、n=4 那一格必须作废，不能写成 0。** 分片只有 1 条时样本标准差未定义——
这是定义域外，不是"零方差"。本批第一版就是在这里错了（把它算成"伪零方差 100%"），现由 `fragment_size` 与 `note` 字段显式标出。

**读数三：组内排序拆组后完全不变，跨组排序会被读反。**

| 拆分 | 组内两两排序翻转 | 跨组排序翻转 |
|---|---|---|
| p=1（不拆） | 0 | 0 |
| p=2 | **0** | **32.8%** |
| p=4 | **0** | **49.3%** |

这是 §11.2 条目 7 的正确表述：**组完整性保护的不是"组内比较"**（组内比较在任何拆分下都自洽，因为归一化是组内的），
**而是"跨组样本能否在同一梯度里被公平比较"**——拆开后每片用自己的均值方差归一化，尺度就不可比了。

### L2 调度侧：分组税

| 变量 | 取值 | 分组税（mean） |
|---|---|---|
| 积压批数 | 1 / 4 / 16 | **0.0%** / 43.7% / 54.7% |
| 组内长度离散度 cv | 0.2 / 0.6 / 1.5 | 20.6% / 43.7% / 56.6% |
| 组大小 n | 2 / 4 / 8 | 27.7% / 38.6% / 43.7% |

**读数四：税的全部来源是"排队时整组扣着槽位不放"。**积压从 1 批增到 4 批，税从 0 跳到 44%——
这不是组大小的函数，而是**并发压力**的函数。语料里没有任何一篇报过自己训练时队列的积压深度，
所以"拆组能省多少"这个问题**在现有报道口径下无法回答**，只能给条件式结论。

**读数五：组越大、组内越不齐，税越高。**n 从 2 到 8 税从 28% 升到 44%；cv 从 0.2 到 1.5 税从 21% 升到 57%。
方向上与"组完整性是硬约束"的直觉一致，但**量级取决于负载**，不能当常数引用。

### L3 判据

| 项 | 值 |
|---|---|
| p=2 拆分的 σ̂ 方差膨胀 | 1.88× |
| 优势信噪比比值 | 0.729（即下降 27.1%） |
| 分组税上限（最宽松负载，cv=1.5） | 61.3% |
| 判决 | **需逐负载判断** |

**读数六：判据是"税 > 信噪比损失"才能转正，两侧都跨得很大，所以不能给单一结论。**
在 cv=1.5 且有积压的负载上，税（57–61%）压得过信噪比损失（27%），拆组可能净正；
在无积压或组内齐整（cv=0.2、税 21%）时，拆组净负。
**这条判据还是必要非充分条件**——它没算上拆组带来的 KV 搬运、跨批版本一致性与 §13.13 五族的可比性损失。

## 这次自查修正了什么

本批的建模错误比结论更值得记，全部是**先跑出看着合理的数字、再回头推翻**：

1. **组臂与轨迹臂不是同一 workload**。初版组臂只跑 `max(g)` 一条、轨迹臂跑全部 n 条，
   等于给轨迹臂多算 n 倍工作，量化出的"收益"纯属口径错误。现在两臂吃同一批轨迹，唯一差别是归还粒度。
2. **`_makespan` 在没有 pending 时把 `now` 直接推到全部结束**，吃掉了轨迹调度的优势，使税恒为 0。
3. **"伪零方差率"把 p=4、n=4 算成 100%**，而那是样本标准差未定义的定义域外情形。
4. **"组内排序翻转率"恒为 ~50%**：初版把组内归一化与跨组归一化混在一个指标里，两边各算各的，
   得到的是随机数而不是效应。现在拆成"组内翻转（恒为 0）"与"跨组翻转（随 p 上升）"两个量。

第 1、2 条由手工追踪一个小例子发现（`[[1,1,1,1],[9,9,9,9]]` 这种两档长度，手算 makespan 才看出臂间工作量不等），

## 边界（引用时必须一并写）

- **进程内解析＋仿真**，没有 GPU、没有真实引擎、没有 verl 跑起来。墙钟是任意虚拟秒，
  **不可与任何论文报值相除**（§19.1 规则一）。
- **分组税是上界**：假设后续轨迹随时可接、无跨批版本一致性与 KV 搬运成本。真实收益只会更小。
- **积压批数是构造参数**，不是从任何系统拟合的；语料内没有系统报过这个量。
- **L1 的奖励模型是高斯近似**（组均值 N(0,1)、单条噪声 N(0,0.25)），不覆盖 0/1 奖励的全部分布形态。
- **不支持**"某系统应该/不应该拆组"这类结论；只支持"拆组的两侧各有多大，以及调度侧的答案取决于积压深度"。
