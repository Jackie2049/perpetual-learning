# C3「同步化基准」的可辨识性：那条 η=0 的步只是冷启动

2026-11-02，M1。支撑 [rollout 调研主文档 §21.8](../../notebook/rollout-performance-research.md)，
接 §21.7「单独报 S 时 η=0 与 η=19 不可区分」之后剩下的那一半。

**不是 GPU 实测，不是任何系统的端到端**。进程内事件驱动仿真，只用标准库，墙钟是任意虚拟秒。

## 一句话结论

**C3 要求 async 收益相对「同栈 η=0 整步墙钟」报，但这条 trace 里"η=0 的步"在因果记账下
只可能是冷启动的第 0 步**——它不是稳态量。拿它当基准，16 格配置的 async 收益**全部被读成
1.000×**（真实 1.10–8.53×），且丢掉 trace 第一步后该估计量 100% 无定义。可替代的估计量
（到达计数＋无等待步）只在「副本数 ≥2 且存在空等」的区间可用，误差 0.4–1.6%，短 trace 上
涨到 5–13%；**它也没有替换掉真正缺的那条同栈 η=0 参照**。

## 为什么做

§21.3（C3）第 3 条规定：async 收益的基准取**同栈 η=0 整步墙钟**；没有该参照时只能报方向、不得报倍数。
§21.7 已经证明"单独报 S"不可区分，但**没有人检验过这个基准本身在可得的 trace 上能不能拿到**。
本实验只问这一件事，顺带把"两种 η=0 形态"与"陈旧窗口造出的 η=0"一起量掉。

## 模型（两处与 §21.7 不同，都是本实验的论点）

事件驱动：`K` 个引擎副本，每副本每 `T` 产出一条完整批（产出速率 `K/T`）；训练侧消费一条批后跑一次
update，耗时 `U`；版本号 = **已完成的 update 数**，只在 update 完成时 +1；批的权重代 = 它**开始生成时**
读到的版本（因果：生成期间权重变化不影响这条批）。

1. **§21.7 的 `sync-pipelined` 在因果记账下不是 η=0**。它的仿真在生成结束时就把版本 +1，
   于是"流水化同步"拿到的批永远标着最新代。本模型里版本只在 update 完成后推进，同一形态必然产生 η≥1
   （`test_pipelined_never_zero_after_start`）。§21.7 的"流水化同步 η 恒 0"是记账产物，
   这一点已在该节标注。
2. **暂停与否只在生成受限时有墙钟差**。`gap = 暂停同步墙钟 − 流水同步墙钟`：K=1 时 0.0995／0.4975／0.9950
   （U=0.1／0.5／2.0，= U·(1−1/steps)），K=4 时 0.0245／0／0（U 较大时队列吸收全部等待）。
   所以「暂停」改变的主要是**版本绑定**，不是墙钟。

## 结果

### Q1：拿「本 trace 的 η=0 步」当基准，16 格全部读成 1.000×

30 种子，`T=1`，`speed = (T+U)/cycle`：

| 配置 | 真实 async | 用 B0 读 |
|---|---|---|
| K1 u0.1／u0.3／u0.7／u2.0 | 1.099／1.298／1.694／1.496 | **1.000**（全部） |
| K2 | 2.196／2.584／2.411／1.496 | **1.000** |
| K4 | 4.365／4.262／2.411／1.496 | **1.000** |
| K8 | 8.527／4.262／2.411／1.496 | **1.000** |

三件事同时成立，缺一不可：

- **B0 的定义集 100% 只来自第 0 步**（`n_eta0_later` 全为 0）：第 0 步用第 0 代批，消费时训练侧还没更新过；
  之后引擎产出的每条批都已读过被训练侧推进过的版本，η 结构性 ≥1。换成「丢前 5 步」的 trace，
  η=0 步为 0，**B0 在 100% 种子上无定义**（`warmup_dependence`）。
- **B0 的值与集群规模无关**（恒 `T+U`）：它读不到 `K`，于是把"加卡带来的收益"全数抹平。
- **B0 恰好等于同步基准**：同一条估计量用在**暂停同步** trace 上是精确的（差 0.0000），
  用在 async trace 上是第 0 步。**它不是"总是错"，而是"读的是哪条 trace"**——这正是不能跨系统复用的原因。

### Q2：替代估计量只在特定区间可用

B2 = `K·horizon/n_arrivals`（到达计数估 T）+ 无等待步的墙钟中位数（估 U），两者都是真能录的字段。

| 区域 | 条件 | B2 是否可用 | 误差 |
|---|---|---|---|
| K=1 确定性 | 从不空等（`no_wait_frac=0`） | **不可用**（Û 无定义） | — |
| K=1 有抖动 | 0.1–2.5% 的步出现空等 | 勉强可用 | +1.3%（U=0.7 档） |
| K=4 主要区间 | `no_wait_frac` 0.75–0.995 | 可用 | **+0.4% ~ +1.6%** |

两条对照守住方法论：

- **B2-naive**（用最小整步墙钟当 U）：无抖动时与 B2 相同，有 U 抖动时低估 U
  （1.713 对 1.700 没问题，但 1.0 档给 1.05–1.11），**它是 B2 在"没有空等步"时的错误降级**。
- **B2'（到达间隔中位数）**：无抖动时因副本同步启动而退化到 0.1（真值 1.0）；
  有抖动时仍系统性偏低（0.96–1.56 对 1.1–1.7）。**中位数不是速率**。

### Q2 后半：短 trace 上 T̂ 的离散偏差

固定 K=4、U=0.3（真值 1.3），只改 trace 步数：

| 步数 | 到达数 | T̂ | B2 误差 |
|---|---|---|---|
| 20 | ~60 | 1.167 | **+12.8%** |
| 50 | ~150 | 1.067 | +5.1% |
| 200 | ~600 | 1.017 | +1.3% |

偏差严格等于 `K/steps`（每步恰好消费 K 条到达），所以它是**结构性的、可解析修正**的，
不需要当噪声处理——但它也说明：**报值长度是估计量误差的一等公民**，短 trace 上 13% 的偏差
会被误读成系统差异。

### Q3：两种 η=0 形态——η 分不开，墙钟差在生成受限区

| 配置 | 暂停同步墙钟 | 流水同步墙钟 | η(max) 暂停／流水 |
|---|---|---|---|
| K1 U=0.1 | 1.0005 | 1.0005 | 1.000／1.000 |
| K1 U=0.5 | 1.5025 | 1.0025 | 1.000／1.000 |
| K4 U=0.1 | 0.2765 | 0.2520 | 6.0／7.0 |
| K4 U=0.5 | 0.5050 | 0.5050 | 3.0／4.0 |
| K4 U=2.0 | 2.0050 | 2.0050 | 1.0／1.0 |

- K=1 时 η **逐位相同**（都是 1.0），墙钟差 0.4975——**η 分不开它们**。
- 墙钟差只在"生成受限"（U < T/K）时出现；一旦 U ≥ T/K，暂停不损失墙钟，**暂停就只是纯粹的
  语义选择（版本绑定）而不是性能选择**。

### Q4：用陈旧窗口"造出" η=0 的代价

K=4、U=0.3、FIFO，窗口从无到 0：

| 窗口 | 丢弃率 | η=0 步占比 | 合成吞吐 | B0 误差 |
|---|---|---|---|---|
| 无 | 0 | 0.5% | 4.26× | 0.0% |
| 8 | 13.4% | 0.5% | 4.26× | 0.0% |
| 2 | 38.3% | 33.5% | 1.95× | +7.6% |
| 0 | **46.7%** | **100%** | **0.65×（慢于同步）** | **+53.6%** |

**用窗口把 trace 改造成"处处 η=0"是可行的，但代价是把 async 自己变成比同步还慢的系统**；
而且此时 B0 仍不等于 `T+U`（读的是被窗口改造后的节奏）。"让基准可测"和"测的是同一个系统"是两件事。

## 对 §21.3／§21.4 的修订（本批已据此改写）

1. **C3 第 3 条补一句**：同栈 η=0 参照**必须来自单独跑的同步配置**，不能从 async trace 内部取；
   从 trace 内取「η=0 的步」结构性只读到冷启动，且与集群规模无关。
2. **C3 增补第 6 条**：若确实无法跑同步配置，唯一有条件可用的替代是「到达计数 + 无等待步」，
   但它要求 ① 到达计数完整 ② 至少存在空等步 ③ 报值长度足够长，且误差量级须一并报出。
3. **§21.7 的修订**：其"流水化同步 η 恒 0"是版本记账产物，因果记账下不为 0。

## 自查修正（均跑通后发现，不是眼看发现的）

1. **版本重复推进**：初版在"消费"与"update 完成"各加一次版本，导致 K=1 的周期变成 8T、速度比全 <1。
2. **事件顺序**：paused 形态的副本在 update 开始**之前**就被重启（同一时刻事件序问题），
   两种 η=0 形态读数一度完全相同。修正为「本时刻事件全部处理完再决定重启」。
3. **gap 的解析式猜错**：先猜 `min(T/K, U)`、又按 `T−U` 写测试，实测是 `U·(1−1/steps)`。
   改测试为结构性恒等式（同时守住"版本只推进一次"与"暂停只延迟重启"）。
4. **`warmup` 开关是死代码**：预设的"稳态起点"全部 1e-9 量级，永远不会走到另一分支；
   删掉，改为"丢弃前 R 步"的读法选择（这才是真正影响 B0 定义集的旋钮）。
5. **浮点精度**：两处测试用 `assertEqual` 比较 0.3 与 0.30000000000000004。

## 边界

进程内事件驱动仿真，无 GPU／无引擎／无 Ray／无 vLLM；墙钟为任意虚拟秒，**不可与任何论文报值相除**
（§19.1 规则一）。K、T、U 是构造参数，不对应任何具体系统的画像；丢批率只由窗口决定，
未建模 DAPO 组过滤等真实丢弃机制。**不支持**"某框架的 async 基线报错了"这类结论；
只支持"在 §21.3 的字面要求下，同栈 η=0 参照不能从 async trace 内取得"这一条。
也不支持"应该改用 B2 报值"——B2 只在有限区间可用，且不能替代真正缺少的同步运行。
