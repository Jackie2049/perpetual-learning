## 2. 生成量账目的完备性

README 用 `generated = 32 + evicted + surplus` 反推每步生成组数，前提是**没有其他逐出通道**。实测：六份日志里 `off_policy/evicted_samples` 与 `rollout_failure/evicted_samples` 一次也没有出现（stale 与 failed 通道为空），所以该恒等式在这些运行里完备。

另核对名字与语义：`evicted_samples` 与 `discarded_surplus_samples` 的计数对象是 **prompt 组 uid**（`replay_buffer.py:357` `len(dapo_uids)`、`:482` `len(surplus_uids)`），不是 sample 条数——指标名里的 "samples" 容易误读，`generated` 用组为单位是对的。

## 3. 把「省等待」与「多生成」分开（回归）

把每步 `gen`／`step` 对**本步生成组数**做回归，斜率各臂共用、只允许截距按 poll 平移（最小二乘 + 4000 次 bootstrap 重采样，按臂分层）：

- 共同斜率：gen **46.0 ms/组**，step **45.9 ms/组**。
- 相对 patched-2.0 的**固定截距偏移**：

| 臂 | gen 偏移（95% CI） | step 偏移（95% CI） |
|---|---|---|
| dbase（原树，默认 2.0） | +0.001s（−0.585, +0.608） | −0.098s（−0.683, +0.498） |
| dp050（0.5） | −1.569s（−1.957, −1.099） | −1.464s（−1.865, −0.991） |
| dp010（0.1） | −1.871s（−2.274, −1.394） | −1.945s（−2.480, −1.425） |

三条读数：

1. **补丁惰性得到独立确认**：dbase 与 patched-2.0 的截距差 CI 跨 0（两种指标都是），即同负载下补丁不改变行为。README 里 dbase 与 patched-2.0 的原始差（gen +0.348s、整步 +0.446s）落在生成量轴上：多 7.58 组 × 46.0ms = **+0.349s**，与 gen 差逐位对上（截距差约 0）。
2. **纯等待的规模**：同生成量下，0.1 比 2.0 每步固定少 **1.87–1.95s**（CI 下界 1.4s）。这与 README 判决 2 用 token 折算的"约 2.3s 量级"同阶，是独立得到的口径。
3. **两笔账能对上**：两臂原始整步差 −1.288s ≈ 固定等待 −1.945s ＋ 多生成成本 15.4 组 × 45.9ms = +0.707s ⇒ −1.238s（残差 0.05s，在 bootstrap 误差内）。也就是说 **−4.9% 已经是"扣掉多生成代价之后"的净收益**，不是把代价漏掉的结果。

## 4. 重复性

2.0 臂三跑整步 26.111／26.511／26.957，跨跑极差 **0.846s**；0.1 臂两跑 25.207／25.286，极差 **0.080s**（约 1/10）。gen 同向（0.727 vs 0.094）。这正是量子化的特征：2.0s 的取整让每次运行落在不同格点，0.1 之后跨跑抖动基本消失。

代价是：单次 2.0 跑可以偏离臂均值约 ±0.4s，所以**均值差 −1.29s 的方向是安全的（大于自身极差 0.85s），但精确幅度应带 ±0.4s 读**；两跑/三跑的均值不能当精确标定。
