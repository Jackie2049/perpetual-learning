# P-3：C 类机制（DAPO 组过滤）的收敛净效应示范

2026-11-01，M1。本材料支撑 [rollout 调研主文档 §13.28](../../notebook/rollout-performance-research.md) 与
§20.3.2 的必补项 **P-3**；不是论文复现，也不是 GPU 性能实测。

## 一句话结论

在本实验的设定下，**"删无信号组"这个 C 类机制本身没有可测的收敛代价**：同种子配对比较，
它只带来训练**步数**上的小幅提升（确定性优势，机制可直接证明），另有一层更小的样本实现噪声；
而它在**生成墙钟**上省下的 31–50% 几乎全部来自跟它捆绑的"无信号早停"，不是来自删组。

## 为什么做

主文档 §13.16 G2 表逐篇核了五个 C 类机制（APRIL／DART／ProRL Agent／QwenGyre／StaleFlow），
结论一致：**全部只报加速与质量终值，无一给"分布偏移的收敛代价 vs 加速收益"的净效应**。
§20.3.2 因此把 P-3 列为投稿前必补项：补一个同 seed、C 开关 on/off 的收敛曲线＋墙钟净账。

P-1（同栈横评）依赖多卡窗口、按分工属 M5 侧算力事项；P-2 需 FP8 训练栈。P-3 是三条未完成项里
唯一可在 M1 权限内推进的——不需要 GPU，只要把机制内核照源码抽出来做受控对照。

**注意**：本实验复刻的是判定与补偿的语义，不是 verl 的端到端训练；端到端未跑，也没有 Ray／vLLM／FSDP。

## 实验设计

一个 bag-of-tokens 二分类策略（14 token：2 个题面事实位 + 12 个填充位），从头训练，奖励 = 是否答对：

- 每组 8 条轨迹（GRPO `n=8`），每步 8 个 prompt → 64 条轨迹；
- 初始正确率 ≈ 0.42–0.45（接近候选 A 锚点 gsm8k acc 0.4917），使"全对／全错"组在训练早期足够常见；
- 30 个固定种子 × 300 步，所有模式共用同一批种子 → 可做配对比较；
- 评测集与训练集 prompt 值不重叠（题面身份换一对新值，只共享填充位参数）；
- 学习率主档 0.1，另跑 0.05／0.2 两档做敏感性（结论方向不变，见 `lr_sensitivity.json`）。

五种模式（每种的改动**逐层叠加**，便于归因）：

| 模式 | 长度 | 无信号早停 | 删无信号组 | 对应范畴 |
|---|---|---|---|---|
| R_nofilter | 14 | 否 | 否 | 基线：标准 GRPO |
| A | 9 | 否 | 否 | A 类：只降方差（短轨迹） |
| B | 9 | 是 | 否 | B 类：改调度（早停） |
| **C** | 9 | 是 | **是** | **C 类：改训练集合** |
| R | 14 | 是 | 是 | 真实 verl 组过滤配置（长轨迹 + 探针 + refill） |

## 口径（必须连同数字一起引用）

墙钟用**统一换算单位**折算，不按秒实测：每条完整轨迹 = 其长度，每个探针 = 4（prompt + 2 个回答 token），
一次空更新 = 1，一个有更新的训练步 = 8。一步成本 = max(生成本步成本, 8)——同步 RL 里 rollout 与 update 串行，
rollout 短时由 update 主导。不建模并发、排队与长尾。

**因此本表的绝对数字不可与任何论文报值相除**（§19.1 规则一），只能五种模式之间横向比较；
也**不能**当成"组过滤能省 X%"的实测结论——那是 P-1 同栈横评要回答的问题。

## 结果（30 种子，lr=0.1，步数 300）

| 模式 | 最终准确率 | Δ vs 基线 | 到 0.9 的墙钟 | 到 0.9 的训练步成本 | 最终总成本 |
|---|---|---|---|---|---|
| R_nofilter | 0.9934 | — | 1.000× | 1.000× | 1.000× |
| A | 0.9909 | −0.0025 | 0.679× | 1.056× | 0.643× |
| B | 0.9959 | +0.0025 | **0.486×** | 0.920× | 0.570× |
| **C** | **0.9986** | **+0.0052** | **0.499×** | **0.888×** | **0.314×** |
| R（真实配置） | 0.9990 | +0.0056 | 0.678× | 0.870× | 0.359× |

配对差值（同种子，30 对）：训练步成本到 0.9 的下降 C −63.5（95% CI ±13.1）、B −45.3（±14.0）、A +31.5（±13.1）。

**三条读数**：

1. **C 相对 B 只再省 3.5% 的训练步成本（0.920→0.888）**——删组本身很便宜。
   真实系统里理由也直观：被删的组在 GRPO 里的优势恒为 0（`(r−mean)/std` 全零），本来就不贡献梯度，
   删掉它换来的是"本步只剩有信号的组"，而代价是要为凑够批大小多跑几轮 rollout。
2. **准确率上 C 高于 B（+0.0028，配对 95% CI ±0.0006）**：轨迹长度固定、不涉样本效率，
   这层差只来自"训练集里保留 vs 丢弃无信号组"改变了每步的梯度分配。配对样本量足以给出显著性，
   但绝对量级很小——**读作"没有可测的收敛代价"，而不是"删组带来收敛加速"**。
3. **A vs B 是最能说明问题的一刀**：两者墙钟都明显降，但 A 在**训练步成本上反而 +5.6%**——短轨迹让每组方差更大、
   需要更多步才到 0.9；B 的早停把省下的生成量换成更高比例的有更新步，步成本反而降 8%。
   **所以"降方差"和"删无信号"是两件不同的事，不能混在一个百分比里报。**

## 边界与不成立的推论

- **不成立的**：不能说"组过滤省了 69% 墙钟"——C 的墙钟优势 0.499× 与 B 的 0.486× 几乎相同，前者并不优于后者。
- **不成立的**：不能说"删组无收敛代价"这一条普遍成立。本实验的任务是单峰、单调可学、无分布偏移风险的
  合成任务；真实 RL 里组过滤会与难度自适应、课程、kl 约束交互，本文没有覆盖那些路径。
- **不成立的**：`R` 模式不是"verl 端到端"，它只说明同一套探针 + refill 在长轨迹上的形态。R 的墙钟 0.678× 比 C 差，
  是因为长轨迹的多生成本来就贵，不能读成"长轨迹下删组更划算"。
- **没有覆盖的**：并发／排队／长尾（§3.1 的 `max_i T_i`）、多卡、真实数据集与真实 actor update 成本、async 档位。

## 它与 §2 判据的关系（对读 §13.16 G2 的补强）

G2 表说五篇 C 类机制"只报终值"。本实验补上了"中间态"，但结论是个**否定式的示范**：在这个最小设定里，
C 类机制的净效应主要体现在**省生成量**而非**改收敛**，且省下的那部分可以完全由不需要改训练集合的 B 类手段拿到。
这恰好把"删组"从"C 类收益的主要来源"位置上挪开——如果后续有工作报"组过滤带来收敛加速"，需要说明加速来自哪个环节。
