# C 类机制账（§13.42）：省下的每步成本，有多少被吃掉

2026-11-02，M1。本材料支撑 [rollout 调研主文档 §13.42](../../notebook/rollout-performance-research.md) 与 §18.9 第 7 章 7.6 节的论点骨架。**不重新训练、不重跑实验**，只从两批既有归档的 per_seed 重算。

## 一句话结论

C 类机制（改变训练集合的那一类）的收益必须分三个口径记：**省了单步样本量、省了每步成本、改没改收敛速度**。把这三个口径叠起来看，本仓库已有的五个机制里**没有一个的墙钟收益可以只记在"省采样量"名下**——`freq` 每步省 72.3% 但墙钟只省 18.7%；`cap` 每步一点没省、墙钟却省 6.3%；`cancel` 每步只省 1.6%、墙钟省 34.0%；§13.28 的 `C`（删组）每步省 44.9%、墙钟反而**变慢 2.7%**。**墙钟与每步成本不是同一个东西，差额来自收敛速度。**

## 为什么做这一步

主文档 §18.9 的 7.6 节与 §16 都把"§13.28＋§13.29 合并成第 7 章论点骨架"列为下一候选。两批实验各自给了结论表，但没有放进同一个算式；而且重算时发现两处需要订正的表述（见下）。本批把账做成可复跑形式，并把口径分层写死。

## 三层口径（缺一层就读错）

| 层 | 量 | 归档字段 | 机制改的是什么 |
|---|---|---|---|
| L1 单步 | `gen_ratio` 生成 token 总量比 | `total_gen` | 采样量 |
| L2 每步 | `cost_ratio` 步成本总量比 | `total_cost` | 每步墙钟（`max(生成, 更新)`） |
| L3 收敛 | `steps_ratio` 到 0.9 的步数总量比 | `steps_to_09` | 收敛速度 |
| L4 墙钟 | `wall_ratio` 到 0.9 的累计步成本比 | `walls_to_09` | 两者叠加 |

缺口算式：`kappa = 1−cost_ratio`、`r = 1−wall_ratio`，`gap = 1 − (1−r)/(1−kappa)`。

- `gap = 0`：每步省的完整兑现到墙钟（L3 中性）
- `gap > 0`：每步省了，但收敛变慢吃掉一部分
- `gap < 0`：墙钟省的**多于**每步省的 —— 收敛变快也贡献了墙钟，这份收益来自"改训练集合"，不能记在"省采样量"名下
- `gap` 无定义（`kappa ≤ 0` 或 `r ≤ 0`）：必须单独归类，不能给一个数

这个 `gap` 就是 §3.3 恒等式 `整步× = 1/(1 − Σ s_k(1−1/G_k) + Σ a_m/T)` 的 C 类特写：机制改的是 `s_k`（阶段占比）与步数，不是 `G_k`（阶段加速）。

## 两处订正（本批与既有正文不一致的地方）

**① §13.29 表第 3104 行的"到 0.9 墙钟比"列分母混用。** `freq` 0.813／`replay` 1.001／`cap` 0.937 是**臂/基线**（种子均值之比），`cancel` 0.660 是**基线/臂**（按臂/基线应为 **1.515**）。已核对四臂的三种分母：

| 臂 | 配对差（基线为分母） | 均值比 臂/基线 | 总量比 | 基线/臂 |
|---|---|---|---|---|
| `freq` | −2482.7 | 0.8128 | 0.8128 | 1.2303 |
| `replay` | +12.1 | 1.0009 | 1.0009 | 0.9991 |
| `cancel` | −4509.9 | **0.6599** | **0.6599** | **1.5154** |
| `cap` | −836.3 | 0.9369 | 0.9369 | 1.0673 |

四臂中只有 `freq`／`replay`／`cap` 的"比值"与"配对差"横向对齐，`cancel` 那一格用的是倒数。**结论方向不受影响**（`cancel` 确实把节省带满：只省 1.6% 每步成本却省 34.0% 墙钟），但**同一列不能既报 0.660 又报 1.515 的语义**——本账统一按"臂/基线"记，主文档 §13.29 表内该格已加注。

**② §13.28"删组自身只再省 3.5% 训练步成本"这一句在本账口径下不成立，原因是分母选错。** 该句是 `C` 相对 `B` 的总成本比 0.920→0.888（相对 `R_nofilter` 的 0.314/0.359）之差。但 C 类机制真正要问的是"相对它捆绑的那一层（纯早停 B）",在配对口径下：

- `C` 的累计**总成本**是 `B` 的 0.551（每步省 **44.9%**）；
- `C` 的**到 0.9 步数**是 `B` 的 0.965；
- `C` 的**到 0.9 墙钟**是 `B` 的 **1.027**——比 `B` 慢 2.7%。

即：删组让每步便宜了近一半，但收敛变慢把它全部吃掉还倒欠。原句"只再省 3.5%"只看了总成本（含 300 步全跑的尾巴），没有看"到目标准确率的墙钟"这一项。**§13.28 ③ 节"注意单位：这是训练步成本差，不是墙钟差"与 ⑤(a) 的表述已同步加注本批结论。**

## 不成立的推论

1. 不得说"`freq` 省了 72% 墙钟"（0.277 是每步成本比，墙钟 0.813）。
2. 不得说"`cap` 省了 6% 墙钟是因为省了生成量"（生成量比 **1.000**，它省的是训练样本，墙钟来自收敛略快）。
3. 不得说"删组加速收敛"（`C` vs `B` 墙钟 1.027，是变慢）。
4. 不得把 `gap` 与其他论文的 `G_k` 混用（`gap` 是墙钟/每步的量纲差，不是阶段加速比）。
5. 更新成本恒 8 单位是本实验的模型假设，真实系统里 update 随批规模变化，故"更新吃掉省额"的幅度是本模型**下界**。
