# C2 事件边界拆分约定的可执行性实证

2026-11-01，M1。支撑 [rollout 调研主文档 §21.4](../../notebook/rollout-performance-research.md)。
不是 GPU 实测，不是任何系统的端到端；是进程内事件图仿真，只用标准库。

## 一句话结论

**C2 约定的"拆分"那一半在最小可观测集下是脆的，"整体记 B2∪B3"那一半是稳的。**
用引擎真能看见的时刻当切点，B2 的相对误差从 −96% 到 +699%，取决于切点选哪一个可观测事件；
而同一个时窗整体报 B2∪B3 在三档配置、30 个种子下偏差都是 **0.0%**。
所以 C2 真正可执行的不是"先尝试拆分"，而是"**默认整体报，只有在能同时给出 t1 与 t2 的独立证据时才拆**"。

## 为什么做

§21（P-5）把 C2 写成报值约定：`B3 = t1 − t0`、`B2 = t2 − t1`，无法分离时整体记 B2∪B3。
那条约定是**写作约定、不是实测**——§0 里已如实标注"语料内无系统按此报值、未冒充转引"。
问题在于：约定说了"无法分离就整体报"，却没说**什么样的情况下算分得开**，
也没量化过分不开却硬拆会错多少。本实验补这一项：把 C2 放进一个能算出真值的最小系统里跑，
让"哪一半能执行、哪一半只是纸面规定"变成可核的读数。

## 模型

一个最小 async-RL 交接，时间原点 `t0 = 0`（训练侧 update 返回）：

| 事件 | 含义 | 生成方式 |
|---|---|---|
| `weight_pack`（0.4s，不吃算力）→ `weight_bcast` | 训练侧的 B3 链 | base `b3`，±15% 抖动 |
| `replica_sleep`（0.3s）→ `kv_migrate` | 引擎侧要把 replica 的 KV 迁回来才能满批 | base `b2`，±15% 抖动 |
| `engine_init`（0.5s，不吃算力） | 与 KV 回迁并行 | — |
| `prefill`（1.0s） | 预热：新权重一到就能开，不必等 KV 回迁 | 依赖 `weight_bcast` |
| `batch_*` × 40 | 每 1.0s 一个请求 | 依赖 `weight_bcast` + `kv_migrate` + `prefill` |

- **t1 = `weight_bcast` 结束**（权重在引擎侧生效，只由广播决定）；
- **t2 = 第一个批请求的起点**；
- 抢占：`dur × (1 + pressure × 在途 busy 任务数)`，让两条链在时间上真正互相影响。

三档配置（`b2`／`b3` base 与 pressure）：近均衡 8/8/0.10、更新侧主导 6/12/0.15、生成侧主导 12/6/0.15。

## 五个读法（全部只用引擎侧可观测事件）

| 键 | 切点取法 | 为什么可能被采用 |
|---|---|---|
| `naive_sep` | 不测量，直接用训练的标称步数当 B2/B3 | 最常见：把配置里的数字当报值 |
| `held_sep` | 把预热 `prefill` 起点当 t1 | 引擎确实能报出这一刻，且以为"权重已到" |
| `ack_sep` | 把广播完成 ack + 50ms 当 t1 | 无先验时最自然的误取：ack ≠ 权重真正生效 |
| `union` | 不拆，从 t0 整体报到 t2 | C2 的保守规则 |
| `micro` | 用单独的 microbenchmark 常数当 B2 | C2 第九条明文禁止的做法 |

**可观测性纪律**：五个读法都只吃 `prefill` 起止、`bcast` 结束、`kv_migrate` 结束、批起点序列，
不读仿真真值；真值 `truth_of()` 单独走一遍仿真内部事件。这条纪律有测试守着
（`test_truth_is_independent_of_readings`）。

## 结果（30 种子/档，相对真实值的误差；B3 一栏略）

| 配置 | 真实 B2 | 真实 B3 | `naive_sep` B2 | `held_sep` B2 | `ack_sep` B2 | `union` 整体 | `micro` 整体 |
|---|---|---|---|---|---|---|---|
| 近均衡 | 1.01 | 9.33 | **+699%** | **−191%** | **−95%** | **0.0%** | −33.9% |
| 更新侧主导 | 0.98 | 14.32 | **+515%** | **−904%** | **−95%** | **0.0%** | −66.4% |
| 生成侧主导 | 5.26 | 7.36 | **+141%** | 0.0% | −99% | **0.0%** | −18.6% |

**读法一：拆分方向没有稳定偏差，误差取决于切点选哪个可观测事件。**
同一个"哪个时刻算 t1"的问题，`held_sep` 在生成侧主导下恰好精确（0.0%）、
在更新侧主导下偏到 −904%——因为那时 KV 回迁比广播**先**结束，拿 prefill 起点当切点会把已经过去的
时间算成负的 B2。偏差符号在配置之间翻转，所以"先试着拆一下再校正"这条路走不通。

**读法二：`naive_sep` 全部高报 B2，且会把 B2/B3 的大小关系读反。**
生成侧主导下 30 个种子里 **27 个**把 B2、B3 孰大孰小读反（标称 12 vs 6，实际 5.26 vs 7.36）。
这正是 §13.13 五族规则要防的那类错：数字都在，只是记在了错的阶段上。

**读法三：`ack_sep` 把 B2 压成 ≈0（−95% 到 −99%），这是最隐蔽的一种错。**
ack 只是"广播发完了"，距权重在引擎侧真正生效还差一截；用 ack 当 t1 会让 B2 看起来几乎不存在，
于是"要不要做在途轨迹管理"这类决策会被一个测量伪影直接否掉。

**读法四：`union` 三档全 0.0%，`micro` 全负。**
`union` 在这里精确是因为本实验的 t0→t2 时窗本身就完整可见；它验证的是
**"整体报"不引入偏差**，而不是"整体报等于万能"——真实系统里 t0 与 t2 的采集覆盖另当别论。
`micro` 三档全负（−18.6% 到 −66.4%），与 C2 第九条的禁令一致。

## 这次自查修正了什么

本实验的自查修正有三处，都是**先跑出数再回头改定义**，记录在此以免后续引用时把过程当结论：

1. **`t1` 的定义**：初版取 `max(weight_bcast, kv_migrate)`，导致"KV 回迁结束"被算成"权重生效"，
   B2 退化为 0、三档配置的读法彼此不可比。改为只取 `weight_bcast` 后才有非零 B2。
2. **批的依赖**：初版让批只依赖 `kv_migrate`，于是批抢在 t1 之前开跑，
   直接否定了 C2"t2 在 t1 之后"的前提（`update-heavy` 一度出现 B2 = −6.71 的物理上不可能值）。
   加上 `weight_bcast` 与 `prefill` 两个依赖后才成立。
3. **相对误差的分母**：B2 可能因两条链同时结束而恰为 0，除零产生 NaN；
   改用整个交接时窗 `B2U3` 做后备分母。

三处都由单元测试抓出来，不是靠眼看：
`test_b2_is_positive_and_bounded_by_base`、`test_prefill_waits_for_weights_not_for_kv`、
`test_batch_starts_exactly_at_t2`、`test_kv_migration_independent_of_bcast`。

## 边界（引用时必须一并写）

- **进程内事件图仿真**，没有 GPU、没有真实引擎、没有 Ray／vLLM／FSDP；墙钟是任意虚拟秒，
  **不可与任何论文报值相除**（§19.1 规则一）。
- 三档配置是**构造出来的**，不是从语料里拟合的参数；它们代表"B2、B3 谁主导"的三种形态，
  不是任何具体系统的画像。
- `micro` 读法取 `0.85 × b2` 是刻意设的一个"看起来合理的常数"，不是从某篇论文抄的。
- 本实验**不支持**"某个系统实际报错了 B2/B3"这类结论——它只说明：在最小可观测集下，
  C2 的拆分侧对切点选择极其敏感，而整体侧稳定。
