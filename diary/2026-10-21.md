## 10:35 — DeepInfer 平民版（魔改适配非旗舰硬件）可行性专题研究

用户立项小专题：评估能否把 DeepInfer 从仅 SM100（Blackwell）/Ascend950（A5）魔改成适配普通硬件的平民版，理清两大问题——对机器的依赖堵点在哪、能否拆除/平移替换。本轮完成堵点定位 + 替代方案调研（中期结论）。

NVIDIA 侧结论：DeepInfer 的 Python 算子抽象层（attention_backend/linear/mlp）本身后端无关，真正绑死架构的是默认调用的三个 kernel 包——FlashMLA（仅 SM100/103）、DeepGEMM（仅 SM90/100）、DeepEP；另有 get_bf16_tflops_limit 在非 SM10x 直接 raise（deep_cluster/hardware/device.py:151-156，llm_engine.py:304 初始化调用）。93 个 tilelang 自定义 kernel 可跨架构但需目标机重编译。

平民替代（子代理调研 vLLM/SGLang/FlashInfer/FlashAttention 官方源码）：MLA→vLLM TRITON_MLA（Triton 编译期适配，fp8 需 SM89+/bf16 需 SM80+，覆盖 4090/A100/H100）；MoE GEMM→Triton/Cutlass（fp8 分组仅 SM90/100）/FlashInfer；EP 通信→标准 allgather-reducescatter。fp8 关键约束：4090 只有普通 fp8 无 block-fp8、A100 无 fp8 tensor core 只能反量化回 bf16。

昇腾侧结论：与 NVIDIA 侧共享同一 Python 抽象，昇腾版 kernel target A5+CANN9.2；910C 是 A2+CANN8.x 不同代际，需重新移植 kernel 而非替换，难度最大。

分层可行性：H100 最容易（DeepGEMM 原生支持、只需换 FlashMLA）、4090 可行（退 bf16 或普通 fp8）、A100 最费（必须 bf16 反量化）、910C 跨代移植难。

价值判断待用户确认：若目标是普通卡跑 DeepSeek-V4，vLLM 已原生支持 MLA+fp8 更务实；DeepInfer 平民版价值主要在验证 ZOS/EPLB/DSpark 系统设计能否平移到普通硬件（研究价值而非工程价值）。

验证范围：源码静态分析（DeepInfer 8b16149）+ 线上替代方案调研；未在 4090/A100/H100/910C 实际编译运行。产出专题笔记（notebook/frameworks/deepinfer-civilian-port.md），登记 notebook/readme 与 WORK。下一步：等目标硬件后建移植冒烟，完成后作为新章节插入 DeepInfer 研究报告。
