## 15:11 — AReaL prompt_mean 切分敏感点：忠实归一化链核验（补强/确认）

### 做了什么（逐行对照真源码 /Users/jackiemac/workspace/AReaL，基线 3b93679）

把 prompt_mean 从 `prepare_policy_gradient_batch` 到 `optimizer_step` 的完整梯度链逐行追踪并数值复刻。

- **step_scale**：`_PromptMeanBatch.for_steps`（loss_reduction.py:115）`step_scale = len(microbatches)/active_groups = M/G`。M 并非直接 `ppo_n_minibatches`，而是 `split_training_batch_into_microbatches`（data.py:1113-1180）经 **DP 同步后的有效 slot 数 `effective_n_mbs`**（L1144-1147），DP=1 时才等于 ppo_n_minibatches，DP>1 可能更大/更小，且**含 transport-dummy slot**（dummy engine_weight=0、无梯度，但仍计入 M 放大分母）。
- **total_weight（关键反证陷阱）**：`engine_weight = rows/global_rows`（loss_reduction.py:200-201），`global_rows` 是「该 minibatch 在 DP 全局的 response 数」，`rows` 是本 rank 该 mb 数——**是 DP 归一化权重，不是跨所有 mb 的 share**。`compute_total_loss_weight` 只在单 minibatch 的 train_batch 内对细 mb 求和，DP all_reduce 后 **total_weight ≡ 1**（非 N）。若误读为「跨所有 mb share」会误推 total_weight=N、与 step_scale 的 N 相消、得出「无切分敏感」的错误结论——**已把此陷阱写进源码笔记 §10.2 核验提醒**。
- **loss_multiplier**：`normalize_loss` 经 fsdp_engine.py:887 传 `multiplier = dp_size`——所有归约统一乘 DP 大小（框架 DP 平均/求和选择），非 prompt_mean 专属，也不随 M 变。笔记 §10.2 原漏掉这一环，已补。

### 结论（确认 + 收敛）

忠实归一化链累计梯度 = `dp_size·(M/G)·Σ_all loss_t·w_t`，**在固定 DP 下随 M 精确线性放大**。升级版 numpy 复刻（verify_areal_prompt_mean_split.py，纳入 total_weight=1 + dp_size + effective_n_mbs）实测：M=1/2/3/4/6 → 1×/2×/3×/4×/6×，**与组边界如何切割无关**（两组 group_sizes 均精确=N）；token_mean 完全不变；dp_size 仅整体常数。**§10.3 核心结论（prompt_mean 随 minibatch 数放大、是唯一受影响归约）得到忠实源码链确证。**

**待实测项收敛**：从「N 倍放大是否成立」收敛为「**该线性放大在真实自适应优化器下是否构成实际训练 defect**」——绝对梯度放大会被 Adam 等归一化部分吸收，故「放大」≠「一定出错」，需 AReaL 环境 ppo_n_minibatches 2 vs 4 对照实际 update 差异。定性由「切分敏感点/待确认」提升为「切分敏感点（高置信源码级确证，缺陷定性待实测）」。

**per-token 路径（分支 2）不抵消切分敏感**（忠实推导 + numpy 复刻 Case 6）：`_build_per_token_loss_output` 得 `loss_numerator = loss·engine_weight·(T_global/W_global)/cp_size`，MCore `finalize_model_grads` 在 DP+CP 求和后 ÷T_global。代入 `loss=(Σ loss·w)·step_scale/engine_weight`，engine_weight 相消、T_global 与分子里的 T_global **精确相消**、`W_global_i≡1`（同 §10.2 total_weight）→ 忠实链 = **`(M/G)·Σ_all loss·w`**：M 线性放大**保留**，且 dp_size 与 P（内层 pipeline mb 数）被 /T_global 消掉（numpy 实测 Case 6：M=1/2/4→1×/2×/4× 精确，P=2/P=1→1.000）。

### 结论（升级 §10.5 缺口）

prompt_mean 的 `step_scale=M/G` 线性放大是 **actor 层共享、跨三条归一化路径稳健**——FSDP2（`dp_size·(M/G)`）、Megatron 默认（`dp_size·(M/G)·P`）、Megatron per-token（`(M/G)`）都一样，**不是**特定 `dp_size·len(mb_list)` 乘子产物。per-token 路径只是换掉常数因子，切分敏感（随 M 线性）不变。**待实测项不变**：真实自适应优化器是否吸收绝对梯度差异，需 AReaL 环境 `ppo_n_minibatches` 2 vs 4 对照（本机无 GPU，等 VPN/远程）。
