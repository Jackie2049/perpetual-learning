**PDL 机制（tilelang 0.1.15 源码级确认）**：
1. **堵点根因在 tilelang 编译管线，非 DeepInfer**：`tilelang/cuda/pipeline.py:244` 固定调用 `MarkCudaSyncCalls(have_pdl(target))`；`contrib/nvcc.py:660` 的 `have_pdl()` 只在 compute capability major ≥ 9（SM90+ Hopper）返回 True。SM89 下 `src/cuda/transform/lower_pdl.cc:44` 只要发现 `pdl_sync`/`pdl_trigger` 就 `ICHECK` 抛 `PDL is not supported`——**编译期硬检查，无 pass_config 可关**（TL_DISABLE_DATA_RACE_CHECK 等均不涉及）。
2. **语义映射 → 改写是机械性的**：`pdl_sync` 标记 kHasGridSync（grid 同步），`pdl_trigger` 标记 kHasTriggerLaunch（允许下游 kernel 经 programmatic dependent launch 提前启动）。顺序 launch（非 PDL）语义下：`pdl_trigger` 可安全删除（下游本就要等前一个 kernel 完成），`pdl_sync` 用第二段已验证的 `T.sync_grid()` 替代。
3. **用量**：28/30 个 `tilelang_ops/cuda/*.py` 源文件用 PDL，共 **56 处 pdl_sync + 8 处 pdl_trigger**（另 vendor/DeepGEMM/third-party/tilelang_ops/swiglu_apply_weight_to_fp8.py 1 处）。少数（如 state_cache.py）按数据规模条件启用（block_size*feature_dim>=65536），本身已有非 PDL 路径。

**真机验证（4090-1，deepinfer-smoke 环境）**：

### 任务与结果

接续三续「43/43 编译扫查」：把每请求必经的 KV 缓存存取两个 kernel（`load_paged_kv_cache_tl` / `store_kv_cache_tl`）从「最小参数编译过」推进为**上游自带 GPU 测试矩阵的数值验证**。方法：`probe_kv_cache_pdlfree.py`——临时隐藏 cuda 包内 `*_pdlfree.py`（**ops 模块遍历 backend 包重导出 `*_tl` 工厂，变体与原件并存触发 `backend symbol collision` 断言失败**，这本身就是移植要点：变体不能留在 backend 包内），`import ops` 后恢复，用 `importlib.util.spec_from_file_location` 按包内模块名加载变体并 monkeypatch 两个工厂，再直接调用上游原始测试函数 `test_load_paged_kv_cache`/`test_store_cache`（与 torch 参考 `*_ref` 逐字节对照；`__wrapped__` 不可用则用原函数）。矩阵：5 布局 × 2 block_size × 3 token 数（1/233/67890）+ store random_invalid 三次 update（负值/幅度扫描/全零量化）。

**结果 A（pdlfree 变体，pdl_sync→sync_grid）：小用例 20/20 PASS，大用例 10/10 FAIL**：
- 1 与 233 token 全部布局 PASS（含 e4m3/fp4/ue8m0 量化、token_interleaved、index/main/SWA、跨页、canary）——**两 kernel 数值语义在去 PDL 后保持（小输入）**；
- 67890 token 全 FAIL：`CUDA_ERROR_COOPERATIVE_LAUNCH_TOO_LARGE`（load grid=3714/1900、store grid=4244）。**根因：tilelang `sync_grid()`（codegen_cuda.cc:3008 → `cooperative_groups::this_grid().sync()`）要求 cooperative launch（cuLaunchCooperativeKernel，grid 全部 block 必须同时驻留），4090（128 SM、每 SM 8-16 block）grid 上限约 1024-4096；大输入超限直接启动失败。上游 PDL 版本（cudaGridDependencySynchronize）无此驻留限制**——sync_grid 替代引入**运行期**新硬边界，编译扫查（小 grid）未暴露。

**结果 B（nosync 变体，pdl_sync 直接删除）：全矩阵 60/60 PASS（含全部 67890 大用例）**。语义依据：两 kernel 的 `pdl_sync` 注释明确是「等待 dependency launch 产生 load_segments/slot_mapping」——顺序 launch 下前序 kernel 由 stream 顺序天然保证完成，同步不需要；删除后无 cooperative-launch 限制。**结论修正：对「等待前序 kernel 数据」型的 pdl_sync（此类是多数），正确去 PDL 改写是删除而非替换成 sync_grid**；sync_grid 只适用于同一 launch 内跨 block 数据依赖的情形。

### 验证范围与边界

数值对照即上游测试矩阵（布局/形状/量化覆盖广，每 kernel 单次编译后多 token 复用，不覆盖全部参数组合）；cooperative-launch 上限为 4090（128 SM）实测，其他 SM 数设备需重测；nosync 删除仅对「等待前序 kernel」型 pdl_sync 安全（load/store 注释明确），其余 41 个 kernel 的 pdl_sync 类型未逐个核对；性能影响（PDL 重叠）仍未测。未改 DeepInfer 上游源码（变体为 /tmp 临时文件 + 本地未跟踪副本）；未做任何 GitHub 操作。
