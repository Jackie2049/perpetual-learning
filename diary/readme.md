# 工作日志

按日期记录 perpetual-learning 的实际工作过程。当前工作与下一步统一见 [WORK.md](../WORK.md)，项目总览见 [README.md](../README.md)。

## 记录方式

- 每天一个 `YYYY-MM-DD.md` 文件。每项实际工作在完成、受阻或终止时留下记录，与成果在同次收尾检查并提交；没有独立成果的学习、调研和失败尝试也记录。同一工作后续提交补充原记录，不重复复制。
- 使用 `HH:MM — 标题`；每次写入前执行 `TZ=Asia/Singapore date '+%Y-%m-%d %H:%M %z'` 取真实时间，不能按轮次或调度间隔推算。跨零点使用新日期，并同步下方索引。
- 日志开头维护简短的“当日回看”：值得回收的成果链接、重要纠正、未完成与等待条件；正文按时间保留探索过程。只归纳已有证据，不把历史推断升级为已验证结果。
- 补记注明何时补、依据哪个提交或实验记录；仅能确定提交时间时明确标注。校正错误时间保留原值与依据，未知执行时间不猜测。
- 用简短文字说明做了什么、为什么做、得到什么结果或经验，并链接对应笔记、工具、实验或贡献材料。
- 日志保留当时的上下文和判断；后续纠正补充新记录，文件迁移时可以修正链接。
- 详细成果维护在所属板块，日志通过链接引用；不要把全过程再次复制进 WORK.md。
- 旧日志中的外部状态、机器状态和验证结论按记录日期理解，使用前按需核实。

## 工作收尾入口

日志是工作完成的一部分，不是可选的事后总结。按“保存成果 → 写日志 → 按需更新 WORK → 检查提交”收尾，记录目的、结果或受阻原因、验证范围和证据入口。

[日志收尾工具](../tools/diary/readme.md) 自动取时、维护日期索引；启用本地 Git 提交检查后，缺少相应记录的提交会被拦截。语义是否完整、技术结论是否可信仍需 Agent 核对；中断后先据实补记，再继续下一项工作。
