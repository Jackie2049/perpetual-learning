# FastVideo 的 65 个布尔开关：8 条「静默失效」逐条查证，**没有一条是缺陷**

<!-- contribution-summary:start -->
**【仓库】** [hao-ai-lab/FastVideo](https://github.com/hao-ai-lab/FastVideo)（统一的视频生成推理与后训练框架，扩池第八批对象）

**【贡献点】** 用 pyflag 扫 FastVideo `36dc971d`（2118 个 `.py`），**65 个开关 / 8 条候选**；逐条绑行号后 **R3 内部默认 4 条**、**R5 独立子工程内部 4 条** ⇒ **真缺陷 0 条**。产出是一条形状结论：多包仓库（`fastvideo-kernel/` 自带 pyproject）必须**按包分组**归因，否则"零生产者"会把子工程内部的包装算漏。[实验与判据](../../experiments/fastvideo-pyflag-triage/README.md) · [扫描器](../../tools/pyflag/readme.md)

**【类型】** 负结论 / 方法沉淀

**【价值评估】** 3 / 10 — 没有可对外的缺陷；留下的是"backend impl 类工厂"这一形状的判据（接收端有 `**extra_impl_args`、发送端不填 = 内部默认，不是失效），以及多包仓库的分组要求。

**【进展】** 2026-11-05 完成扫描与逐条归因：`verify_findings.py` **24 checks 0 failed**、`--selftest` **3/3**、`classify.py` 8 条全覆盖。纯静态、**未装 fastvideo、未跑推理、未上 GPU/NPU、未触上游**。

**【大白话讲明白】**

FastVideo 是给视频生成模型（扩散类）做加速推理和微调的框架。和前面查过的 LLM 推理引擎一样，它有很多"开不开某个功能"的开关。这批扫出 65 个，其中 8 个看起来"有分支、但代码库里没人给它传值"——按以往经验这正是"设了不生效"的典型。

逐条查下来，**一条都不是**：

- 四条是**内部默认值**：说明里写着"用不用 bf16 计算"、"用 128x4 还是 8x4 的量化布局"、"流式生成开不开队列"、"用不用 nvfp4 量化格式"。它们都是**框架自己选好的**默认，调用方只传公共参数、其余交给默认——这是设计，不是坏掉。其中"128x4 布局"那条更明确：三个调用点全部**写死传 True**，只是仓库里没人传 False。
- 另外四条落在 `fastvideo-kernel/` 这个**独立子工程**里（自带打包配置），是内核层的内部调试参数，只由同一子工程里的包装函数传。

**这批真正学到的东西是**：一个仓库里有多个独立的 Python 包时，"全仓搜不到有人传"会把子工程内部的转发漏掉，得**按包分开数**。而且"一堆按后端实例化的 impl 类"这种写法天然会有大量默认参数，它们不该被当成失效。

**【What–Why–How】**

- **What：** FastVideo `36dc971d` 上 65 个带布尔默认值、在函数体内按它分支的形参里，8 个没有仓库内直接生产者。
- **Why：** 前七批都在 LLM 推理与 RL 训练；视频生成是生态里另一个大块，形状不同（一张 `FastVideoArgs` 配置面 + 各 backend 的 impl 类），要检验判据在新形状上是否仍成立。
- **How：** pyflag 扫出 65/8；逐条用 AST 找传值形态（关键字、位置实参、`**kwargs` 兜底、partial）后分类：4 条内部默认、4 条子工程内部。**边界**：只覆盖函数形参，不覆盖 `FastVideoArgs` 这类 dataclass 字段（该框架的主要配置面）；"内部默认"只说明"仓库内没人改它"。

## 三、方法产出

### 1. 多包仓库要按包分组

`fastvideo-kernel/` 有自己的 `pyproject.toml` 与调用约定。四条候选全落在那里，把它们与主包
混在一起看，"零生产者"会把子工程内部的包装函数算漏。⇒ 扫描读数先**按包分组**，再逐条归因。

### 2. backend impl 类工厂 = 内部默认的高发区

`AttentionImpl.__init__` / `StreamingVideoGenerator.__init__` / `_mm_fp4_op` 这类形状：
接收端有 `**extra_impl_args` / `**kwargs`，发送端只传公共参数。这是第七类易错点
（`**kwargs` 兜底）的接收侧镜像，**不该按"失效"处理**。

### 3. `always` 与 `producers_total` 回答的不是同一件事

`use_128x4_sf_layout` 三个调用点都显式传 `True`：生产者存在、只是值不变。判"这个开关能不能配"
要看生产者形态，判"值会不会变"才看 `mode`。

## 四、为什么这条不对外

8 条里没有一条对用户造成"配了没反应"：三条内部默认是设计意图，一条是子工程调试参数，
其余是测试或子工程内部使用。**不对外，无待授权的上游动作。**
