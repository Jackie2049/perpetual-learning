# 工作日志收尾

每项工作收尾时留下一条可回看的记录，包括学习、实现、验证、否定结论、失败尝试和受阻。无需记录每一次命令；同一项工作的后续补充可以更新原记录。日志规范见 [diary/readme.md](../../diary/readme.md)。

## 使用

依赖 Python 3.9+（含系统时区数据）和 Git，无第三方包。在项目根目录执行：

```bash
python3 tools/diary/diary.py append --title "本项工作的具体标题" --body-file /tmp/work-record.md
```

正文由 Agent 按真实工作撰写，包含目的、结果或受阻原因、验证范围、成果链接；没有独立成果文件时直接在日志中留下结论和证据。也可通过标准输入传正文。工具自动填写 Asia/Singapore 日期、时间和日期索引，不自动生成结论，不自动暂存文件。

检查记录、维护当日回看，并将本项成果、日志及必要的索引和 WORK 更新一起暂存后执行：

```bash
python3 tools/diary/diary.py check
```

## 自动检查

每个新克隆启用一次，之后普通 `git commit` 自动检查，无需依赖会话重读规则：

```bash
python3 tools/diary/diary.py install
```

检查器读取**暂存区**：有提交改动时，必须有新增或实质补充的近期日志正文；时间不能在未来，日期须已纳入索引，正文中的仓库相对 Markdown 链接须指向纳入版本管理的文件或目录。允许前一天的记录随跨零点工作提交，不篡改原时间。更早的遗漏用当天的补记记录来源。

检查还会对照HEAD保全已有的时间/标题条目：新增近期记录不能抵消其他条目被移除，保留标题却清空原有正文也会拒绝。正文完全相同的改标题可一对一匹配，但仅改标题仍不算新增工作。日期文件删除或改名按源文件移除处理，不依赖Git的rename相似度判断。需要有意删除、合并或迁移历史时先交用户决定，不用`--no-verify`绕过；常规纠正保留原条目并追加说明。

该保护不比较正文的语义或逐句完整性：同标题下的非空改写、当日回看删除、已存在于HEAD的历史损失不在拦截范围。只在更新了本工具且已接入hook的克隆上检查提交，不能拦截其他克隆、直接远程写入或绕过hook的动作；同步后仍需核对异常删改。

相对链接扫描跳过顶层围栏代码，避免把 Python 下标后接调用等示例误认成成果链接。支持至少三个反引号或波浪号、最多三个前导空格；结束围栏须同类、长度不短于开头且没有正文尾缀。围栏后的真实链接仍正常检查。这是限定范围的扫描修正，不是完整 Markdown 解析；行内代码、缩进/嵌套代码及引用式链接的旧扫描行为未改变。

只修改日期索引、当日回看、标题或旧日志不算本项工作已记录。失败/受阻也须有记录；没有成果文件的工作可以提交日志本身。同一工作拆为多个提交时，后续提交在原记录中补充本次内容，无需复制一整条日志。

安装只修改当前仓库的 `core.hooksPath`，已有 hook 配置或 pre-commit 时拒绝覆盖。已有 hook 可调用 `python3 tools/diary/diary.py check` 接入。Git 的 `--no-verify` 或修改 hooks 配置可绕过本地检查；Agent 不应通过绕过检查解决漏记。

检查器不判断技术结论真假、正文是否充分覆盖每个任务，也不能拦截尚未提交的工作或进程被杀。Agent 在任务切换/正常结束前完成记录；异常退出后，下一轮先核对成果与日志，只按可核实证据补记。外部链接不联网验证，页内锚点不验证。历史日志不要求批量改格式。

测试使用隔离的临时 Git 仓库：

```bash
python3 -m unittest discover -s tools/diary -p 'test_*.py' -v
```

## 已提交历史的只读比对

并行克隆可能已将日志截断提交到远端，本地 hook 不能追溯拦截。`git diff` 可查看原文差异；本工具在其上提供条目级清单，便于逐项核对，无需另建同步或合并器。

```bash
python3 tools/diary/diary.py compare --base HEAD --target origin/main
```

先自行同步远端引用。方向为 base → target：输出两个固定 commit OID、保留及新增条目数，并逐项列出旧条目删除和正文变化。旧条目全部保留且正文相同时返回 0；发现删除、任意正文改写（包括非空改写），或引用/文件解析错误时返回 1。它不操作工作区、暂存区、refs 或 hook 配置，不自动拉取、合并、修复或推送。

比较键为日期文件路径、`## HH:MM — 标题` 的时间和标题；正文只忽略首尾空白，内部文字或空白变化均需核对。改标题、改时间或迁移日期文件按旧键删除、新键增加报告，不沿用提交钩子的一对一改标题豁免。重复键或日期文件为符号链接等非普通文件会拒绝解析。

两个分支分叉时，target 尚未包含 base 的本地新增记录也会报告删除，**不等于远端已覆盖历史**。合并前可分别对照共同祖先的 OID；合并提交生成后、推送前，再核对两边的完整历史是否都进入结果：

```bash
python3 tools/diary/diary.py compare --base HEAD^1 --target HEAD
python3 tools/diary/diary.py compare --base HEAD^2 --target HEAD
```

这两条仅适用于当前 HEAD 确实是双亲合并提交的情形；有意纠正旧正文时仍会返回 1，需要人工逐条审视，不能以改标题或忽略退出码消除差异。此命令尚未自动接入 hook，现有 `check` 行为不变。

比对只覆盖现有格式的时间条目，不检查当日回看、索引、条目顺序、技术结论或 Markdown 全部语义；两端都已缺失的历史也无法发现，须选择仍保留原文的旧提交。它是同步核对助手，不是远程写入防护或历史恢复工具。
