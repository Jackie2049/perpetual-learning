# anchors — 核验"主文档的数字是不是从归档来的"

## 用在哪

AGENTS.md 要求经验能追溯到实际执行。但"追溯"一直靠人翻——这个脚本把它变成可复跑的一件事：
**读实验归档的 JSON，重算主文档声称的比值，逐项比对**。

```bash
python3 tools/anchors/verify_anchors.py            # 全部检查
python3 tools/anchors/verify_anchors.py --list     # 只列检查项
python3 tools/anchors/verify_anchors.py --selftest # 负向对照，证明检查器真能抓错
```

退出码：0 = 全部一致；1 = 有不一致项。

## 它核什么、不核什么

| 核 | 不核 |
|---|---|
| **这个数字是不是从这份归档里来的** | 结论对不对 |
| 声称值 vs 归档重算值是否在容差内 | 归档本身是不是算对了 |
| 归档文件是否还在 | 解读是否合理 |

**数字对得上，结论仍可能解读错**——这是两件事。本脚本只负责前一件。

### 第三类检查：文件存在性

文档说「某文件未入库」，但它其实已经入库——这类**关于仓库状态的自述**也会过期，
而且比数字过期更隐蔽（数字至少会被引用时发现，这种断言没人复查）。

实例（2026-11-03 发现）：主文档多处写「G3／G5／G6 备忘未入库」，实际三份文件
**都已入库并被 git 跟踪**（`ae9fd3fa1` 等）。四处断言全部过期。

检查器只在**未标注订正**时报：若该处已写「已订正／已过期」，视为人已处理。

| 故意写错 | 判定 | 预期 |
|---|---|---|
| 1.526 → 2.5 | 不一致 | ✓ |
| 1.526 → 1.53（差 0.004） | 不一致 | ✓ |
| 1.526 → 1.527（差 0.001，容差内） | 一致 | ✓ |
| **引旧放置的 update_actor 1.211 当新放置** | **可被区分** | ✓ |

### 一次差点误报（务必记住）

## 负向对照（重要）

只报 OK 的检查器说明不了什么。`--selftest` 用三个已知偏差验证它真能抓：

| 故意写错 | 判定 | 预期 |
|---|---|---|
| 1.526 → 2.5 | 不一致 | ✓ |
| 1.526 → 1.53（差 0.004） | 不一致 | ✓ |
| 1.526 → 1.527（差 0.001，容差内） | 一致 | ✓ |

## 边界

- **覆盖面很小**：只登记了 7 条链 30 个左右的数字，而主文档有数百个数字。**不要把它当成"全仓已验证"**。
- **新增的两类里有一类是"跨归档"**：3+1 与 2+2 分属 `summary.json` 和 `reanchor-summary.json`，两次运行各有自己的 1 卡基线，不能拿两个 speedup 直接相除。
- 容差按各链的精度需求设（候选 G 1.5e-3、恒等式 2e-2、气泡 1e-2），不是统一标准。
- `SKIP` 只表示归档缺失或结构变了，**不等于通过**——脚本会把它单独计数，不计入一致。
- 加新检查只需在 `CHECKS` 里多写一行 `check(...)`，但要**同时想清楚容差**。

## 为什么值得做

§20.3.5 把 P-1 的完成度判为"约一半"，依据是候选 G 的 1.526／1.942×。这类数字一旦与归档脱节，
整个可发表性判断就悬空了。本脚本让"核对"从一次性人工动作变成**随时可重跑**的事。

### 第二次误报（2026-11-03，比第一次更该记住）

扩表时登记「3+1 比 2+2 慢」一项，先按 `(new/old − 1)` 写，得 −16.0%，与正文的 19.1% 对不上；
接着又怀疑是正文错了，把主文档三处 19.1% 改成 16.0%。**正文是对的**——"A 比 B 慢 X%"
以 B 为分母，16.878／14.173−1＝19.1%；16.0% 是拿 3+1 当分母才有的数（＝1−1/1.191）。

**教训**：核对脚本报不一致时，先假定**检查器**写错了。这次连改动主文档的念头都差点落地，
而它会把一个正确的数字改成错的。**在改被核对象之前，先手工把算式算一遍、把分母写出来。**

### 分母口径：这一条比数字本身更容易错

同一天还发现一处真的串用：§13.42 结果五原写"pC1 比 A 快 16.3%"，而不绑定 A 组给 16.8%、
四跑均值给 16.0%——**16.3% 恰好是结果一里 B 慢于 A 的组间差**，两对不同的跑次被写进同一句。
这类错误里每个数字都真实存在，只有写明分母才看得出来。`--selftest` 因此增加两组：
组间差必须只用不绑定四跑（混入 taskset 格会变 16.89%）、SHM 时间比必须能与错误模型值区分。
