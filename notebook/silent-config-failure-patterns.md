# 静默失效的四种形态：配置声称生效、代码路径不通、用户无感

<!-- contribution-summary:start -->
**【仓库】** [perpetual-learning](https://github.com/Jackie2049/perpetual-learning)（本仓库方法论沉淀）｜涉及 verl、rLLM

**【贡献点】** 把本仓库 2026-11-02／03 两天内独立发现的**四条同类缺陷**归纳为一张形态表，并给出可机械检测的部分与必须人读的部分。四条共同点：**配置或文档声称生效，实际代码路径不通，且不给任何提示**。

**【类型】** 方法论沉淀

**【价值评估】** 7 / 10 — 模式清晰、可复用，且已用工具（[pyflag](../tools/pyflag/readme.md)）在四个框架上验证过检测可行性；但四条样本集中在两个框架，普适性未验证。

**【进展】** 已归纳四形态与两种检测手段；工具与扫描报告已入库。**未发布任何上游内容**。

**【大白话讲明白】**

开源项目里常有这种坑：配置项写了、文档也说了怎么用，但真正干活的代码根本没读它。用户打开开关、跑完训练、什么也没变，也没有任何报错或警告——只能怀疑自己配错了。

两天里在 verl 和 rLLM 上各碰到两例，形态还都不一样：有的是"根本没人传参"，有的是"判断函数写错了恒为真"，有的更糟——"只有副作用生效了，主功能没生效"。这篇把它们归成一张表，并说明哪些能靠工具扫出来、哪些必须人读代码。

**【What–Why–How】**

- **What：** 四条独立发现的共性结构，以及每种形态的检测手段。
- **Why：** 这类缺陷的危害不是"崩溃"而是"给出错误的信心"——训练照跑、日志正常、指标正常，唯独那个开关没起作用。它比报错更难发现，因为没有任何信号。
- **How：** 归纳四形态（无生产者／守卫恒真／副作用半生效／默认值指向不可用路径）；给出可机械检测的两项（生产者扫描、断言扫描）与必须人读的两项（配置项的实际读取点、失效形态是"不生效"还是"只生效一半"）。**边界**：样本为 2 框架 4 例，不构成分布统计。

## 一、四种形态

| # | 形态 | 实例 | 用户看到什么 |
|---|---|---|---|
| **1. 无生产者** | 函数有形参、有分支，但**没有任何调用点传值** | verl `tiled_mlp`：配置项与文档齐全，`workers/engine/` 下 10 个引擎目录 grep 全为 0 | 配了没用，无提示 |
| **2. 守卫恒真** | 判断"有没有某能力"的条件**永远成立** | rLLM `has_async = isfunction(...) or ... is Tool.async_forward`，而 `Tool.async_forward` 是真实 `async def` ⇒ 对任何子类恒真 | 关闭不了，或走错分支 |
| **3. 副作用半生效** | 主功能不通，但**开关的其他读取点照常生效** | verl `use_prefix_grouper`：引擎侧没人传 ⇒ 前缀共享不发生；但 `ray_trainer` 仍按它改组级均衡、跳过重排 | **只付代价、不拿收益** |
| **4. 默认值指向不可用路径** | 配置的**默认值**指向一条实际走不通的路 | rLLM Fireworks：默认 `router_replay: R3`，但路由矩阵装不进 Tinker/Fireworks 的训练帧 | 默认配置即有隐患 |

**形态 3 最危险**：另外三种至少是"什么都没发生"，而它让用户**付出了约束的代价却以为买到了加速**。

## 二、能扫与不能扫

### 能机械检测（已工具化）

| 检测 | 工具 | 判据 | 覆盖哪种形态 |
|---|---|---|---|
| **有无生产者** | [`scan_unwired_flags.py`](../tools/pyflag/readme.md) | 消费者存在 & 生产者为零 ⇒ 候选 | **只有形态 1**（部分触及形态 3） |
| **测试能不能失败** | [`scan_test_assertions.py`](../tools/pyflag/readme.md) | 零断言 / 断言只在注释里 / 用 print 当判据 | 不针对形态，是**放大危害**的因素 |

**必须说清的覆盖度**：

| 形态 | pyflag 能扫吗 |
|---|---|
| 1 无生产者 | **能**（这正是它的设计目标） |
| 2 守卫恒真 | **不能**——需要理解判定表达式的语义，工具只能数出现次数 |
| 3 副作用半生效 | **部分**——能找到"无生产者"，但"另一半是否生效"要人读所有读取点 |
| 4 默认值指向不可用路径 | **不能**——需要判断那条路走不走得通 |

一个实证：TM-010 的 `router_replay` **不在** rLLM 的 pyflag 扫描结果里（那 11 个 flag 中没有它），
因为它是"默认值"而非"布尔形参"。**不要把形态表当成工具能力表。**

2026-11-03 在四个框架跑过（开关数／判为候选）：**verl 37／8、SkyRL 39／7、OpenRLHF 5／0、rLLM 11／2**。
**报"有生产者"时可信；报"无生产者"时仍须人工排除间接传参**（`**kwargs`、配置对象属性）。
扫描报告：`tools/pyflag/scan-verl-6879e1ab07.json`、`scan-skyrl.json`、`scan-openrlhf.json`、`scan-rllm-4e828c8.json`。

### 必须人读

| 需要人读的 | 为什么工具做不到 |
|---|---|
| **配置项的实际读取点** | 工具看的是"名字出现几次"，不是"谁消费了这个值"。TM-006 就是靠 grep 10 个引擎目录全为 0 才定案的 |
| **失效形态是"不生效"还是"只生效一半"** | 需要理解该开关在系统里所有读取点的语义。TM-005 的副作用正是这样发现的 |
| **默认值是否指向不可用路径** | 需要知道那条路走不走得通，通常要读下游模块 |

## 三、为什么这类缺陷特别值得报

1. **没有任何信号**：不报错、不警告、日志正常、指标正常。
2. **测试常常帮凶**：rLLM 的 `test_python_tool` 之所以"过"，正是因为缺陷吞掉了异常——**测试依赖缺陷才通过**（见 [scan_test_assertions](../tools/pyflag/readme.md)）。
3. **文档加剧误导**：TM-009 的 docstring 明写「If use_async is None (default)」，而签名默认是 `False`——文档描述的是一个从未被执行的分支。

## 四、检测顺序（建议）

```
1. 拿到一个"应该有作用但似乎没作用"的配置项
2. 扫有无生产者（工具）        → 有生产者？转 3；无？候选成立
3. 人工核实间接传参路径        → 排除 **kwargs / 配置对象属性
4. 找该名字的**所有**读取点    → 判断是"完全不生效"还是"只生效一半"
5. 检查默认值指向             → 默认值那条路走得通吗
6. 查上游是否已有人报          → search API，注意 301 迁移后的 repo slug
```

## 五、边界

- **样本只有 2 个框架 4 例**（verl 2、rLLM 2），**不构成分布统计**。不能据此说"这类缺陷很普遍"。
- 四条均为**静态取证**，未经真实训练验证其影响面；各条的"用户看到什么"是按代码路径推断，不是实测用户报告。
- 形态表可能不完备——将来遇到第五种应当补进来，而不是硬塞进现有四类。
- **未发布任何上游内容**；四条候选的对外动作均待用户逐项授权。
