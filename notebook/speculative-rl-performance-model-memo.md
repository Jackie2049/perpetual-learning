## 1. 目的与结论

speculative decoding 迁移到 RL rollout（spec-for-RL）已有多篇独立工作（§13.12 D11 spec 簇六篇 + §13.13 账中 T2 spec 家族），但**没有任何统一性能模型**把它们的收益表达式对齐。本文把证据盘点为三轴（接受率 × 陈旧性 × 长尾/批交互），给出统一模型骨架（理论提案，未验证），并列出每篇对齐该模型所缺的字段。

**核心结论（负面证据 + 开放缺口）**：现有六篇 spec-for-RL 的指标分母互相不可换算（墙钟缩短% vs rollout 阶段缩短% vs tokens/s vs ms/token），接受率要么不报（Heddle/FP8-RL）、要么以不同口径报（BubbleSpec 平均接受长度含恢复/bonus token、EfficientRollout 按 iid 公式反推、DAS 自建模非普适），且**没有一篇同时报告接受率-位置曲线 × policy 版本差 × 批内轨迹分布**。因此三轴统一模型当前无法被任何一篇拟合；本文给出骨架与数据补全清单。**引擎级实测已为部分轴提供锚点（2026-10-30）**：轴 1 接受率-位置曲线/形状/提议器强度（候选 C 与候选 C2，§6/§7）、轴 3 批规模方向与批内长度分布→makespan（候选 C2/DSD/候选 D，§7/§4/§8，其中批 makespan 由总工作量决定、上端分位数效应属 L3 系统级），轴 2 版本差仍无数据（N/A）。

## 3. 统一性能模型骨架（理论提案，未验证）

### 3.1 单轨迹基线（经典 SD 数学，Leviathan 2211.17192 / Chen 2302.01318）

draft 生成 k 个候选 token（每 token 成本 c_d），target 并行验证一次（成本 c_v），逐位置接受率 α。在 iid 近似下期望每验证轮接受 1/(1−α) 个 target token，单轨迹期望时间：

```
E[T_i] ≈ L_i · (k·c_d + c_v) / (1−ᾱ_i)
```

其中 ᾱ_i 为轨迹 i 的有效平均接受率；相对纯自回归（单 token 成本 c_t）的加速：

```
S_i = c_t / ((1−ᾱ_i)·(k·c_d/c_t + c_v/c_t))  ·  （分子为每 target token，分母为每验证轮成本）
```

该基线只含 L1 轴（token 级执行成本与接受率），不含 RL 特有轴。

### 3.2 三轴扩展（本骨架的核心）

**轴 1：接受率-位置曲线 α_i(t) 与轨迹长度交互。** α 随位置漂移（前缀易匹配、长轨迹尾部退化）；长轨迹（16K–64K）的成本由 α(t) 整条曲线而非单点 ᾱ 决定。BubbleSpec 的平均 accept length、EfficientRollout 的 iid 反推、DAS 的自建模都只是该曲线的某种压缩，口径互不换算（§2）。观测匹配（ObsSpec 66.45%）与 token 接受率是不同量，不可混用。

**轴 2：policy 版本差（staleness）对 α 的侵蚀。** RL 每步更新 policy；draft 来源分三类，陈旧性语义不同：
- 冻结 draft 模型（Medusa 骨干冻结等）：α 随 policy 漂移单调退化，无更新机制；
- 当前 policy 量化/压缩 draft（EfficientRollout 每步 RTN W4、FP8-RL 真 FP8 policy）：紧跟版本，但引入数值失配（FP8-RL 需 token-level TIS 修正）；
- 历史数据后缀树 draft（BubbleSpec/DAS/Seer/TailSieve）：树内容来自旧步骤，DAS 用滑窗 16/32 刷新降权旧匹配，但**无一篇报告 α 随版本差 v_gap 的量化曲线**。

统一写法：ᾱ_i(v_gap) = ᾱ_i^fresh − Δ(v_gap)，Δ 依赖 draft 来源类型；ReSpec 式 drafter 联合 KD（只更新 drafter）使 draft 持续跟踪 target，属另一类——以训练成本换 α 维持，该成本须计入净收益（C 类边界，§4 训练侧）。

**轴 3：批内轨迹分布与 sync makespan。** sync RL 的 T_rollout ≈ max_i T_i（§3 模型）：makespan 由**轨迹 i 的 T_i 分布的上端分位数**决定，不是批均值。即使批平均 ᾱ 高，α 方差大的轨迹成为 straggler 支配 makespan：

```
T_rollout^spec = max_i E[T_i]（含气泡），加速比 = max_i T_i^base / max_i T_i^spec ≠ 批均值加速比
```

EfficientRollout 的 active batch 单调缩小论证（短响应先完成、剩余长尾使 SD 更有利）正是轴 3 的正面利用；Heddle 的 tokens/s 吞吐指标看不见 makespan；DAS 以"长轨迹决定 makespan"为动机但报的是 rollout 时间缩短%，非整批 makespan。**【引擎级实测限定（2026-10-30 第三十二批候选 D，§8）】**：上式在 **L2 引擎级不成立**——引擎级连续批处理按 token 步进齐头推进、批 makespan 由总工作量/解码速率决定（长度异质批 makespan 1.000×/0.994× 同质基线，§8 发现 1）；`T_rollout ≈ max_i T_i` 的成立边界是 **L3 系统级**（同步 barrier/权重刷新/训练-rollout 串行），引擎级连续批处理是该式的反例。EfficientRollout「active batch 缩小→长尾受益」在引擎级仅有微小正方向（≈ −0.6/−1.0%，§8 发现 2）。

### 3.3 完整骨架表达式

对同步 RL 的一个 rollout 批：

```
T_rollout^spec(B) ≈ max_{i∈B} [ L_i·(k·c_d(v_gap) + c_v) / (1−ᾱ_i(v_gap)) ] + 气泡项(B)
```

其中 c_d/c_v 本身可随批量大小与引擎重叠能力变化（小批量时 per-request 成本上升）。该式把三轴压缩为一个可拟合对象：**每篇论文只需补报 (α_i(t), v_gap, 批内长度分布) 三个字段即可对齐**。当前六篇均缺至少两字段。

## 6. 候选 C 实测数据的模型交叉校验（2026-10-30 收尾第二十八批）

用候选 C 归档（`experiments/rollout-g8-candidate-c/raw/summary.json`，8 组合 ngram-spec，vLLM 0.24.0+cu129 引擎级）对本文三轴骨架做首次定量检查。四项发现：

1. **A(p) 指标语义与 E[L] 恒等式（回原文锚定）**：vLLM 的 A(p) 为**无条件逐位置接受率**（`metrics.py num_accepted_tokens_per_pos` 跨请求按步聚合），四组合全部精确满足 `E[L] ≡ 1 + Σ_{p=1..5} A(p)`（512_8：1+0.390=1.390、512_16：1+0.392=1.392、2048_8：1+0.274=1.274、2048_16：1+0.326=1.326，rounding 内与 mean_accept_len 全等）——**E[L] 不是独立指标而是曲线的积分**，读整条曲线比读单值信息量大。

2. **曲线形状非 iid（次几何/自增强）——轴 1 的首个形状证据**：按 E[L] 反推的 iid ᾱ（k=5 几何级数 (1−α^5)/(1−α)=E[L]）为 0.21–0.28，其预测 A(p)=ᾱ^p 尾部快速衰减（512_8 预测 [0.282, 0.079, 0.022, 0.006, 0.002]），实测尾部显著更重（[0.207, 0.088, 0.047, 0.034, 0.014]，p4/p5 为几何预测的 **5–55×**）；条件接受率 A(p)/A(p−1) 随位置上升（512：0.21→0.72–0.82 后 p5 回落 0.41/0.51；2048：0.14→0.82–0.92）——**ngram 提议器自增强**（首个 draft 被接受后，后续 n-gram draft 沿已确认上下文继续生成、匹配率升高）＋请求异质（难/易提示词混合）。结论：**轴 1 的 α(t) 曲线形状携带 ᾱ 之外的真实信息；iid 公式只在聚合值意义下是上界，"贴合 iid 界"不可引申为逐位置 iid**；以 A(p1) 代 ᾱ 会低估 E[L]（1.26 vs 实测 1.39）。

3. **吞吐负项的每代际核算（模型包围实测）**：按每代际 token 数核算——每次 spec 迭代 target 前向处理 k+1 tokens/请求（k draft＋1 确认位）、产出 E[L] tokens，AR 每次 1 token；**线性成本参照 S_lin = E[L]/(k+1) = 0.21–0.23**；实测 spec/AR ∈ **[0.16, 0.31]**（512_8 0.159／512_16 0.274／2048_8 0.307／2048_16 0.271）——参照**包围实测**（2048_8 高于参照 45%＝验证前向在长上下文批下亚线性；512_8 低于参照＝小批串行化开销）。反推验证前向有效成本 c_v^eff/c_t = E[L]/(spec/AR) ≈ **4.1–8.7**（对照 k+1=6：接近每 token 1×，偏差为批效率±）。**盈亏条件 E[L] > c_v^eff/c_t ≈ 4–9：ngram E[L]≈1.3 结构上不可能为正——弱提议器在 k=5 下净负是模型预测而非异常**。经典 SD 账"c_v≈c_t"（S≈E[L]≈1.39 应更快）在本机小批/低并行下失效；六篇正收益论文批规模更大（8–64 GPU），c_v 亚线性更强——**c_v^eff 的批规模依赖正是轴 3 与引擎重叠能力的交汇点，本批给出方向锚点**（b8→b16 时 spec/AR 从 0.16 升至 0.27，验证前向成本随批下降）。**【第三十一批 JIT 修正注记（不改本批历史数值）】**：512_8 的 0.159 经第三十一批复核为首个 spec 组合 Triton JIT 首编译污染（归档 wall 4.99s 含约 +2.8s 编译），JIT-warm 修正后 512_8 spec/AR≈0.368——本批"模型包围实测"的方向结论（净负、盈亏需 E[L]≈4–9 远超 ngram 1.3）对修正值同样成立（0.368 仍 <1 且低于参照的包围区间上移后仍被 E[L]≈4–9 净负约束）；"b8→b16 上升"表述由修正后的 b8 高→b16 平台缓降替代（见 §7 发现 3 注记）。

4. **口径修正**：per-draft-token 接受率（accepted/drafted）实测 5.5–7.9%，per-position A(p1) 14.4–21.2%，**两量不同不可互换**（§4 上一版"~5.5–10.2%"中 10.2% 无实测出处，已修为 5.5–7.9%）；§4"（ᾱ 低 → 1/(1−ᾱ) 大）"算式方向写反（ᾱ 低 → 1/(1−ᾱ) 小 → E[L] 小 → 收益不足，意图正确）已修正。

## 7. 候选 C2 三轴补测：提议器强度 × 批规模 × 方差方法学（2026-10-30 收尾第二十九批）

承接候选 C（ngram b8/b16）用 vLLM 0.24.0+cu129 补 16 组合（Qwen2.5-1.5B 单 4090、gsm8k 提示词、temp 0.7/top-p 0.9、max_tokens 128、k=5、GPU 5；04:44–05:13 UTC、0 失败、GPU 释放回 1MiB）：**in{512,2048}×b{32,64}×{ar,spec}（8 组合，批规模扩展）＋in{512,2048}×b{8,16}×{ar,draft}（8 组合，Qwen2.5-0.5B-Instruct drafter 学习式强提议器）**。归档 `experiments/rollout-g8-candidate-c2/`（raw 33 文件＋summary/anchor/README＋3 脚本，35 文件 sha256 与服务器逐文件全匹配；独立核验见专项 §16 第二十九批/第三十批与当日 diary）。四点发现：

## 8. 候选 D 实测对轴 3（批内长度分布→sync makespan）的交叉校验（2026-10-30 收尾第三十三批）

承接候选 C（§6，轴 1 曲线/形状）与候选 C2（§7，轴 1 强度×轴 3 批规模），用候选 D 归档（`experiments/rollout-g8-candidate-d/raw/summary.json`，4 构成×{ar,spec}×2 iter＝16 组合，vLLM 0.24.0+cu129 ngram、Qwen2.5-1.5B 单 4090、GPU 5、batch=8、temp 0.7/top-p 0.9、max_tokens 128（RX8 逐请求 64–256 均值 128））对本文轴 3 的**批内长度分布→makespan** 关系做首次定量检验。四点发现：

1. **轴 3 模型核心主张（上端分位数支配 makespan）在 L2 引擎级被否定——批 makespan 由总工作量/解码速率决定**：构成 MIX（[512,512,1024,2048,2048,2048,4096,4096]，均值 2048 与 H2048 同均值同总量）vs 同质 H2048（8×2048）：**AR 批 makespan 1.0647 vs 1.0646s = 1.000×**——长度跨度 512–4096 的异质批与同均值同质批 makespan 完全相等；RX8（8×2048、max_tokens 逐请求 64–256 均值 128）1.0587s = **0.994×**——短响应先完成反微快（EfficientRollout「active batch 缩小→长尾受益」引擎级微小正方向 ≈ −0.6/−1.0%，但 b8 已容下全部请求、释放槽位不显著加速剩余请求）。**引擎级连续批处理按 token 步进齐头推进、批 makespan 由总工作量/解码速率决定（§3.2 式 `max_i E[T_i]` 的引擎级不成立）**——sync RL 经典 straggler（上端分位数税）在 L2 引擎级被吸收，属 **L3 系统级现象**（同步 barrier/权重刷新/训练-rollout 串行）；模型轴 3 表达式对引擎级为反例、对系统级仍为合理模型（§3.2 已加边界注记）。

2. **spec 模式下 prompt 异质有 +7.2% 交互成本（轴 1×轴 3 交汇）**：MIX spec/H2048 spec = 2.9026/2.7079s = **1.072×**——ngram 提议+验证与异质批 prefill/调度串行化交互（spec 禁 async scheduling、逐请求 first-token 1.33–1.73s 分散）——**长度异质在 spec 下不再被引擎吸收**（AR 吸收但 spec 串行化显式化）；response 异质仍微负 RX8 spec = **0.990×**（短轨迹先完成释放 KV 槽，长尾受益微小正方向）。

3. **A(p) 与长度分布交互（不足以翻正净负）**：MIX p1 0.186 略降（长上下文稀释）但 p4/p5 0.029/0.026≈2× H2048（0.016/0.016）——批内 4096 长上下文请求 ngram 深位后缀匹配更好；RX8 p4/p5 0.006/0.004 降（短响应预算请求 ngram 上下文收益少）；均不足以翻正净负（spec/AR 2.53–2.84× 全净负、与候选 C/C2/DSD 同栈一致；spec first-token 1.33–1.73s vs AR 0.05–0.36s）。

4. **方法学边界（T_i 分布的引擎级测量口径）**：offline 模式不填 per-request e2e_latency（first_token_latency 有），逐请求 T_i 完整分布需 serve-mode 扩展；本批证据以批 makespan＋逐请求 first-token 为准；seed=0 两 iter wall 差异 <0.5%（H2048 ar 1.0661/1.0632、spec 2.7329/2.6829）。
